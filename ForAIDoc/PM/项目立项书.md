# P4Deck 项目立项书

> 文档角色：长期产品愿景与初始立项范围；不是当前执行清单。
> 当前阶段：Windows 本机私用验收，见 [Windows 本机私用 TODO](Windows本机私用TODO.md)。
> 长期目标平台：Windows、macOS；macOS 不属于当前阶段。

## 项目背景

官方 P4V 客户端在日常使用中存在信息密度高、操作路径长、大型 Workspace 下容易卡顿、错误反馈不友好以及界面陈旧等问题。P4Deck 希望参考 UGit、Fork、Tower 等现代版本管理工具，构建一个快速、清晰、安全的 Helix Core 桌面客户端。

## 产品定位

P4Deck 面向使用 Helix Core 的开发者、技术美术和内容制作人员，重点解决：

- 快速理解当前 Server、User、Workspace 和 Stream 状态。
- 用更少步骤完成 Sync、Edit、Reconcile、Diff、Changelist 和 Submit。
- 大规模文件列表仍保持流畅。
- 风险操作具有预览、范围确认和明确反馈。
- 兼容现有 P4CONFIG、ticket、trust 文件和服务器策略。

首版不是服务器管理工具，也不追求完整复制官方 P4V 的全部功能。

## 核心目标

以下目标是产品、架构和实现方案的最高优先级约束；功能交付不能以牺牲这些目标为代价。

1. **前端与 P4 操作彻底解耦**：所有 P4 查询、命令执行、解析、重试和取消均在后台异步完成。P4 Server 响应慢、命令长时间运行或失败时，前端主线程仍须保持可交互，不能出现界面卡死。
2. **大数据量下依然流畅**：CL、CL 文件、Workspace、Depot、历史、日志和搜索结果必须使用虚拟列表、增量加载与按需渲染；包含大量文件的 CL 仍可流畅浏览、选择和预览。
3. **缓存优先，降低 P4 Server 负载**：优先展示有效的本地缓存，并通过失效策略、请求合并、去重、防抖和增量刷新减少重复查询；禁止因界面重渲染、切换视图或轮询产生无意义的大量 P4 请求。
4. **现代、清晰且高质量的 UI**：界面应符合当代桌面应用的视觉与交互标准，在信息密度、层级、反馈、主题、键盘操作和无障碍之间取得平衡，不照搬传统 P4V 的陈旧体验。
5. **低资源占用**：持续控制内存、CPU、后台任务和磁盘缓存开销；空闲时避免高频轮询和无效计算，大列表与长时间运行场景不得出现无界内存增长。
6. **Windows 与 macOS 双平台支持**：核心功能、交互语义、数据安全和性能标准在 Windows 与 macOS 上保持一致；平台差异通过适配层处理，并纳入持续构建和兼容性验证。

## 产品原则

1. **响应性优先**：网络和 P4 操作不得阻塞前端主线程；耗时任务必须异步、可取消并提供明确状态。
2. **本地状态优先**：先展示缓存，再渐进刷新服务器数据。
3. **安全优先**：Revert、覆盖文件、大范围 Sync 和 Submit 必须明确目标范围。
4. **复杂功能按需出现**：首页只放高频操作，高级 Integration 和 Resolve 使用独立流程。
5. **键盘友好**：高频操作支持快捷键和命令面板。
6. **性能可衡量**：为启动、刷新、搜索、滚动、资源占用和操作反馈建立指标。

## MVP（P0）

- 提供默认关闭、用户按需打开的内置 P4 命令行窗口，并继承当前连接与 Workspace 上下文。
- 提供默认关闭、只由用户手动打开的 P4 Log；新日志不自动展开，未查看 Error 仅在底部日志入口显示红点，并支持脱敏、过滤和操作关联。
- 自动发现或手动配置官方 `p4` CLI。
- 创建、测试、编辑和删除连接。
- 处理 SSL trust、ticket 登录、登录过期和常见连接错误。
- 列出并切换 Client Workspace。
- 展示 Server、User、Workspace、Root、Stream 和连接状态。
- 展示 Edit、Add、Delete、Move、Unresolved 和 Out-of-date 文件。
- 从第一次实现起，对 CL、CL 文件、Depot、历史、日志和搜索结果强制使用虚拟列表与增量加载。
- 查看本地文件与 Have/Head Revision 的文本 Diff。
- 执行 Edit、Add、Delete、Move、Revert、Reconcile 和 Sync。
- 创建、编辑、删除 Pending Changelist，并通过多选、拖放或命令在 CL 之间移动文件。
- 首版支持 Shelve、更新/删除 Shelf、Unshelve 和 Shelf 内容预览。
- CL 查询支持关键词、状态、用户、Workspace、路径、Stream 和自定义时间段等组合过滤。
- CL 查询支持隐藏分支合并/集成产生的干扰 CL，无法可靠判断时标记为“疑似合并”而非直接隐藏。
- 校验并 Submit Changelist，展示进度和最终 Change 编号。
- 查看近期提交记录和文件历史。
- 保存非敏感设置和缓存，不记录密码或 ticket 内容。

## 后续范围

### P1：公开 Beta

- Stream 切换、文本冲突 Resolve。
- 完善 Shelf 跨 Workspace 场景和基础 Swarm 链接。
- 文件锁、独占检出、Ignore 原因、历史版本下载。
- 操作队列、取消、重试、通知和自动刷新。
- 完整命令面板和键盘操作。

### P2：后续版本

- 图形化 Merge、Integration 和 Stream Graph。
- 图片、音频等二进制资源 Diff 插件。
- Swarm Review 工作流。
- 管理功能、protections、labels、jobs 和自定义工具。

## 明确非目标

- 不重新实现 Helix Core 网络协议。
- 不捆绑或分发 Helix Core Server。
- 首版不实现完整服务器管理能力。
- 不追求与官方 P4V 逐项功能对等。
- 首版不正式发布 Linux 安装包，但架构保留未来支持能力。

## 质量指标

- 热启动到缓存 Workspace：P95 小于 800 毫秒。
- 首个有效 Workspace 状态：排除网络耗时后，P95 小于 1.5 秒。
- P4 命令运行、超时或失败期间，界面输入、滚动和导航保持响应；禁止在前端主线程同步等待 P4。
- 50,000 条记录搜索与筛选：小于 50 毫秒。
- 通过虚拟列表流畅浏览 100,000 条文件记录。
- 禁止先使用全量 DOM 列表再安排后续性能优化；虚拟化是功能完成条件的一部分。
- 相同查询在缓存有效期内必须复用结果；并发相同请求必须合并，界面重渲染不得触发额外 P4 查询。
- 空闲状态不得高频轮询；大列表、长日志和长时间运行场景不得出现无界内存增长。
- 超过 500 毫秒的操作必须展示活动状态或进度。
- 日志、诊断数据和进程参数不得出现密码或 ticket。
- 目标达到 WCAG 2.2 AA 对比度要求并支持键盘导航。
- Windows 与 macOS 必须进入持续构建和核心工作流验收矩阵。
