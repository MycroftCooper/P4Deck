## 已落地模块

- 手工文本三方合并：`WorkflowService` 从 `p4 resolve -n -o` tagged record 读取 base/from/type，再以 `p4 print -o` materialize 明确 revision；`manual_merge.rs` 负责有界解码、行级三方冲突块、文件 snapshot、编码保持及带 backup 的原子替换。`ManualMergeEditor` 只在内存编辑正文，保存与 `resolve -ay` 使用两个独立一次性 token 和 mutation-lane 复检。
- Swarm 基础链接：Connection Profile schema v3 增加可选、规范化的非敏感 base URL；统一 builder 覆盖 Submitted/Pending/Shelf change、Depot 文件与精确修订。按钮、右键和命令面板共用同一 action，Rust opener 在 OS 调用前以活动 profile/context generation 做最终 CAS 和 route allowlist；不包含 API、登录、评论或 Review 创建。完整矩阵见 [Swarm 基础链接](Swarm基础链接.md)。
- P4VFS 虚拟 Workspace：仅支持在 Windows 新建 Workspace 时写入 `altsync`，preflight 检查 Server/CLI 2023.1+、`P4ALTSYNC` 与连接身份，创建后回读 Client spec 验证 Sync Mode；Workspace 页展示标准/虚拟同步及未就绪原因。普通 Sync 继续复用现有受控流程，由 P4 CLI/P4VFS 透明处理按需下载。不转换已有 Workspace、不安装 Agent、不修改系统环境。完整边界见 [P4VFS 虚拟 Workspace](P4VFS虚拟Workspace.md)。
- 基础 Stream 切换：Streams 页右键菜单与详情按钮进入 `Preflight → Confirm → Execute → Verify/Recover`。默认只用 `p4 client -s -S` 更新 Client 视图且不碰文件；显式选择同步时才在二次干净工作区复核后执行非 force `p4 sync //client/...#head`。一次性 token 绑定 profile、Server/User/Client/Root、generation、源/目标 Stream、Client/Stream spec digest 与风险快照；打开文件、未解决文件和同步模式下的 reconcile 风险会阻断。
- Stream Graph 前后端只读闭环：`StreamGraphService` 用 `p4 streams -T ... -m 5001` 读取官方字段并在客户端再次执行 scope/text/deleted 过滤，构建 server node + parent edge 森林。缺父、循环、自父、重复与未知字段保持显式 partial/orphan/unknown；5,000 条硬上限、连接代次缓存及一次性 snapshot cursor 防止无界扫描、错连接和重放。`StreamGraphPage` 直接消费该契约，以确定性分层、虚拟化可访问树、过滤/分页/取消/重试、详情/键盘/390px 和既有安全切换对话框完成 UI；不存在的父节点不伪造，也不猜 merge/copy 状态。主入口位于 Streams 页，Activity Bar 不重复展示，Dock/popout 能力保留。
- Branch Mapping 前后端闭环：`BranchMappingService` 和 `p4/branches` 提供强类型 list/detail、结构化 View、只读双向 `integrate -n` 影响预览，以及 create/edit/delete 的独立 preflight/confirm。列表/游标、Context/generation、owner、spec digest、unknown/comment round-trip、Client mapping、mutation lane/TOCTOU 与危险删除确认全部在 Rust 权威校验；写命令从不带 `-f`，写后必须再次读取确认。`BranchMappingsPage` 直接消费该契约，提供虚拟列表、过滤/分页/取消/重试、原样详情/View、正反只读预览和只经专用 preflight→confirm 的编辑器；Tauri adapter 与 Browser Mock 同步，Mock 明确 simulated。
- 管理员强制解锁已移除：P4Deck 只保留普通用户的 Lock/Unlock；他人锁明确阻断并提示联系管理员。当前代码不包含专用服务、IPC、共享契约、Mock、UI 或 `unlock -f` 构造器，generic GUI 命令也不能绕过普通安全流程。管理员在应用外使用受控后台工具处理。
- Global Search Stream/Shelf 前后端闭环：继续使用 `GlobalSearchService` 与现有分组/facet/不可变快照，不另建搜索协议。Stream 直接复用 `StreamRepository` 的官方字段和 5,001 sentinel，匹配 path/name/owner/type/parent/description 并保留 deleted/virtual/task；Shelf 先有界扫描 501 条 metadata，再以最多 8 个批次 × 16 个 change 的 `describe -s -S` 搜索 depot path，每 shelf 256 文件、总 20,000 文件、20 秒预算。触顶通过 `partialReason` 明示；一个 shelf 无论命中多少文件只返回一个稳定结果。cursor 额外绑定 profile/page size 并单次消费，Browser Mock 同样模拟快照、replay/cancel/partial。`SearchPage` 已正式扩为七类，复用 App 显式导航状态定位 Streams 或打开独立 Shelf detail；不解析 P4 输出、不另发 Shelf 深搜请求，也不通过全局自定义事件导航。
- Terminal / P4 Log 工作流：两者注册为正式全局 panel，复用 Dockview/Tauri 原生窗口协议、版本化浮窗恢复与通用 `window_placement`。命令面板/前端快捷键/活动栏由单一命令目录驱动；runtime binding 使用不透明 token，连接代次变化取消并隔离 Terminal 旧任务/输出。安全执行仍只走 `P4Runner`，不增加认证旁路。
- 全应用 Action / 恢复：37 项前端命令目录覆盖连接/Profile、全部 `CommandBar` 主操作、只读页面、Diagnostics、设置与窗口操作；目录记录稳定 ID、分组、快捷键、上下文、风险和确认策略，mutation 统一回到既有状态机。Windows 原生顶栏菜单及 `app-command` 事件桥已按本人验收反馈移除，连接管理继续进入 Settings 的“已保存连接”，Changes/Navigate/View 由侧栏、页面和命令面板承担。validator 改为校验前端 union、生产定义、Action 文档与右键菜单台账的真实完整性，不再校验不存在的 Rust 菜单镜像。新增只读 retry、活动页自动刷新与通知适配层；mutation 永不自动重放，刷新和通知均绑定连接代次并清洗敏感信息。
- 文件审查闭环：`DiffRequest/FileHistoryRequest/RevisionGraphRequest` 共用 scope identity；`FileService` 通过 `fstat/filelog/print` 获取权威元数据和文本，Workspace 有界读取并计算 SHA-256。Diff 使用有界行级 unified diff；History 返回稳定游标页；Revision Graph 解析真实 integration records，而非按 revision 伪造分支线。
- 审查安全与性能：binary/symlink/缺失/超限均为显式状态，两侧保留 size/digest/type；4 MiB/100k line/8 MiB diff、500 history page、2,000 graph revision 与 30 秒/128 项缓存防止无界内存。operation group 支持取消，Runner 继续负责超时、输出上限、日志与 Journal。
- 审查竞态闭环：`reviewRequests.ts` 用完整 request owner identity + 本地 sequence + `AbortController` 管理 Diff/History/Graph 首屏、分页、双版本/节点 Diff 与跨文件占位展开。旧 owner 不能提交结果、错误、loading 或 cache；页面数据使用 owner envelope 在连接/profile/generation/路径/selector 变化的首帧即隐藏。分页拒绝重复 cursor，失败保留可信集合，Graph 节点/边稳定去重。
- 后端取消闭环：`P4Runner::begin_operation_group` 让根 operation token 覆盖审查请求的全部子命令及子命令间隙；History/Graph 子命令使用 `:history/:graph` child ID，Diff/Shelf 保持 `:fstat/:left/:right/:shelf`。服务返回和缓存写入前同时复核 scope generation 与 group cancellation，因此取消或漂移结果不会进入缓存。
- Shelf 分页闭环：`get_shelf_detail` 首屏冻结最多 10,000 文件的后端快照，1～500 条一页；opaque cursor 绑定 active profile、P4 Context、context generation、Shelf mutation generation、change 与 page size，并通过随机 cursor ID + 服务端 issued offset 映射一次性消费，边界篡改同样拒绝。刷新、连接切换和相关 mutation 清空快照并推进代次；错绑、重放、过期和代次漂移返回结构化错误。前端复核 request generation 与完整 scope，列表分页和 preview/diff 使用独立取消域，失败保留可信集合并从首屏重启。

## 安全边界

### 凭据 Threat Model 与限制

- 防护对象：恶意或误输入的 Terminal 参数/stdin、父进程继承的 P4 凭据环境、P4 CLI/代理/触发器返回的 stdout/stderr/JSON 敏感字段、旧版日志数据库，以及日志/Journal/诊断导出二次传播。
- 信任边界：前端预检只负责及时隐藏与恢复入口，Rust spawn 前策略才是权威拒绝点；Runner 输出、持久化写入、持久化读取和最终导出是四道独立防线。
- 非目标：不能防止具有本机管理员/同用户文件读取权限的进程直接读取用户自己配置的 P4 ticket/trust 文件，也不替代操作系统凭据库、磁盘加密或真实 SSL/SSO/MFA 安全评估。上下文脱敏不会猜测无标签、未知且从未注册的任意裸 token；已知认证命令被阻断，已知 secret 与带语义标签输出会被覆盖。

- Terminal 不是系统 Shell，只解析 `p4` 子命令与参数。
- `-p/-u/-c` 由当前 Workspace Context 注入，Terminal 不能传入全局连接参数。
- 通用 Terminal 在 spawn 前阻止 `login/login2/logout/trust/tickets/passwd/set/configure`，并统一识别大小写、`p4` 前缀、前导短/长全局参数、引号/空白、`-P value`、`-Pvalue`、`P4PASSWD=`、`P4TICKETS=` 与认证 input。Settings 的窄 Trust/Login/Logout API 不经通用 Runner，仍可正常工作。
- `security.rs` 是 Rust 侧唯一 credential policy/redaction pipeline：结构化 JSON 敏感 key、Ticket/password/passwd/P4PASSWD/P4TICKETS、Authorization/Bearer、多行标签下一行及本次调用已知 secret 均在 `OperationEvent` 创建前替换；不使用全局 32-hex 规则。
- Runner 明确移除继承的 `P4PASSWD/P4TICKETS/P4TRUST`，只恢复 Context 中受控的 ticket/trust 文件路径。受控 Login 请求类型不支持 Debug/Clone/Serialize，密码不复制并在调用后 zeroize。
- 禁止 `-P` 和 `P4PASSWD=`；登录、改密和敏感命令不进入历史。
- `login/logout/trust` 不能通过通用 Runner 或通用 IPC stdin 调用，只能进入受控连接服务；密码仅作为单次 `login` stdin 写入子进程，不进入 Context JSON、OperationEvent、SQLite、命令历史或返回错误。Ticket 文件只传路径，不读取或返回内容。
- 连接服务把 SSL 未信任、未登录、Ticket 过期、网络、权限、配置、外部 SSO/MFA 等结果映射为稳定 camelCase 状态和恢复动作，前端不需要解析 P4 stderr；Trust 只接受当前请求绑定的 Server Context 和经校验 fingerprint，不开放任意 trust flag。
- 前端只依据结构化 `state/recovery` 呈现恢复动作；连接验证固定走 CLI 发现、服务器连接、登录状态三段。Context 有未保存修改时禁止验证/Trust/Login；保存只产生 `notTested`。Trust 需要当前 server、当前 fingerprint 和显式勾选三者一致，切换连接即清除确认。
- 密码输入使用非持久化 React state，提交时先复制到单次请求再立即清空 UI state；不写入 Storage、Context、URL、通知、错误或历史。外部 SSO/MFA 不显示普通密码表单，只允许用户完成外部流程后重新查询状态。所有连接动作使用请求代次与同步 busy guard，旧连接响应和重复点击不会更新 UI。
- Runtime 的 connection generation 在 Context 保存及连接/认证状态变化时递增；依赖 P4 Context 的 Workspace、Streams、Pending、Submitted、Files/Depot 等页面以该代次重建，避免同文本 Context 的重新登录继续展示旧连接响应。
- profile 文档是唯一持久化事实源：`schemaVersion=3`、revision、activeProfileId 与 profile 集合；profile 只包含 UUID v4、名称和 allowlist `P4Context`，其中 Swarm base URL 可选且不承载凭据。schema v2 原位迁移为 v3 且不猜测 Swarm 配置；旧裸 Context 在写入新 schema 前生成不含未知敏感字段的 allowlist `.legacy.bak`；损坏/未知版本/原子替换失败不覆盖原文件或内存状态。
- Settings 的连接草稿只让用户编辑 Server/User/Workspace 与 P4 高级配置；`cwd` 不再作为可编辑字段。手填、目录选择、创建回读和旧已保存连接均复用有界 Workspace 目录查询，按完整草稿身份精确匹配 Client 并派生 Root；任何 Server/User/Client/executable/charset/trust/tickets/Swarm 变化都会使旧 Root 失效。目录候选的 `rootStatus/selectable` 只是本机 hint；活动保存、首次活动创建、激活与 Workspace 切换都会重新证明 Client 存在、读取 `client -o` spec，并用目标 `-c/-d` 的 `p4 info` 核对 effective Client root 后再按 revision/generation CAS 提交。未连接、Root 缺失/空白/相对/不存在/非目录、Host 不匹配或尚未验证时不自动扫描本地 Workspace，也不回退进程/exe 目录。
- 活动 profile/Workspace 切换固定为“无旧 Client/cwd 的 `p4 info` / `p4 login -s` 认证探测 → 精确 Client spec/effective Root 复核 → expected revision/generation 原子提交”。连接服务为 discover/info/login-status/trust/login/logout/switch-verify 写入脱敏结构化日志，只保留 state、errorCode、duration、operation ID 与连接哈希，不保存 stdin、raw args、Ticket、Server/User/路径。提交后取消全部 Runner operation，清除 Submitted/Search/status cache 与 Submit/Workflow token；失败不改变旧活动连接。
- Stream 切换只能经 `preflight_stream_switch` → `confirm_stream_switch`。GUI 通用 `run_p4` 拒绝 `client/stream/switch` 写入口；token 一次性使用并绑定完整连接身份、active profile、generation、源/目标 Stream、模式、Client/Stream spec 和风险 digest。确认阶段占用同 Server mutation lane 并完整复检；从不调用 `p4 switch`、`client -s -f`、`clean` 或 `revert`，也不声称自动回滚。
- Submit 只能经 `preflightSubmit` → `confirmSubmit` 状态机执行。泛化 FileAction 和 GUI 来源的通用 `run_p4` 均拒绝 submit；确认 token 一次性使用并绑定 Server/User/Client/Workspace、Context generation、CL 内容和文件状态，确认阶段在同 Server mutation lane 内复核后只执行 `p4 submit -c <编号 CL>`。
- Shelf/Unshelve/Resolve 只能经对应 `preflight*` → `confirm*` API 执行。它们与 Submit 共用一次性 token store，绑定 Connection/Workspace/generation/CL/显式文件集合/server digest 与本地内容；泛化 ClAction、FileAction 和 GUI `run_p4` 旁路均被关闭，Terminal 语义不变。
- Rename/Move 只能经 `preflightRenameMove` → `confirmRenameMove` 执行。`FileAction::RenameMove` 已移除，GUI `run_p4 move` 被拒绝；一次性 token 绑定 active profile、Context generation、两端映射、source opened state、目标 CL 和 preview digest，确认在 mutation lane 内重查后才执行单条参数数组 `p4 move`。目录、跨 Workspace、覆盖、P4 filespec 元字符（`@`、`#`、`%`、`*`、`?`）和 Windows 仅大小写改名固定返回 blocker。
- 普通 File Lock/Unlock 只能经 `preflightFileLock` → `confirmFileLock` 执行，并在 mutation lane 内重查、以 tagged `fstat -Ol` 做写后验证；结果保留 partial/cancelled/unknown 且不自动回滚。普通接口没有 force 参数，P4Deck 也不提供管理员强制解锁 API；泛化 FileAction、Terminal 与 generic GUI `run_p4` 的 lock/unlock 旁路保持关闭。
- Shelf/Unshelve/Resolve 对话框只接受与打开时目标快照一致、未过期且带 token 的 ready 预检。替换/删除 Shelf 需要危险确认；Unshelve 不提供 force 覆盖；Resolve 只显示后端允许的可执行策略。结构化 partial/rejected/failed/cancelled/unknown 或任一文件 blocked/unknown 均不显示成功，并按 refresh advice 局部合并 Pending、失效文件状态及关联 operation/log。
- Pending 创建/编辑/删除经 `mutatePendingChange` 执行；文件移动则只经 `preflightMoveFiles` → `confirmMoveFiles`。Edit 从写前权威快照保留 `Files:`，不会把已移动文件意外放回 Default。移动 token 固定 Server/User/Client/Workspace/generation、来源/目标 CL、depot path 集合和 opened/lock 摘要；确认逐文件参数数组执行 `p4 reopen -c`，复核最终归属并返回逐项结果。成功只合并来源/目标 `refreshedChanges`，部分成功、取消、失败或刷新不确定时保守失效相关状态且不显示全成功。
- Pending 展示通过 `pendingCache.ts` 复用 QueryClient 内存快照并异步保存到 IndexedDB；按运行模式、Profile、Server/User/Client 和工作区路径隔离，重启或页签重建可恢复。5 分钟内复用本地数据，过期后后台刷新，搜索、排序和展开不发 P4 请求。刷新失败保留已有列表，操作结果局部合并，后台刷新结果不能覆盖更新的操作结果；持久快照仅用于展示，写操作仍经后端复核。冷读将 pending/opened/shelves 三项独立读取并发执行，每 100 个编号 CL 批量 `describe -s -m 1` 读取完整描述与 Jobs，保留范围验证和 operation group 取消。
- SubmitDialog 将无 token 的 blocked 预检视为合法结果，分别显示 confirmed blocker、confirmed warning 与 unknown；只有 ready、目标一致、token 有效且用户确认整个 CL 时才调用 `confirmSubmit`。结构化 rejected/failed/cancelled/unknown 均保持失败语义，并按 refresh advice 更新 Pending、Submitted 与 Workspace。
- 进程使用 `Command` 参数数组，不进行 Shell 字符串拼接。
- Fixture 使用固定 localhost 端口；E2E 显式注入 executable/server/user/client/ticket/trust，隔离 P4CONFIG/P4ENVIRO/P4PASSWD，不读取或回退到用户真实 P4 环境。
- 系统本地路径操作不接受可执行文件或额外参数：拒绝 depot path、相对路径、控制字符、不存在路径、Workspace 越界和符号链接越界；macOS 使用固定 `/usr/bin/open`/系统应用选择器，Windows 使用 Explorer/`SHOpenWithDialog`，全程不经过 Shell。
- Swarm 外链只接受活动 profile 中规范化的 HTTP(S) base URL，禁止凭据/query/fragment/控制字符；前端只构建官方 `/changes/<id>` 与 `/files/<depot-path>?v=<rev>` 路由，Rust 以 profile、generation、origin、部署子路径和 route allowlist 再验证后才交给系统浏览器。错误和通知不回显 URL，避免未来误配置中的敏感片段传播。

## 性能约束

- CL 采用窗口化 DOM；P4 Log 每次最多渲染 100 条游标页并按需追加，不再一次拉取/渲染 10,000 条。
- CL 查询携带 `requestGeneration`，新查询结果只能由最新代际写入界面。
- 关键词输入 250 ms 防抖；Rust 将 P4 支持的范围、状态、用户、Client 和时间条件优先下推。
- 单次 UI 查询设置 20,000 条保护上限；后续继续扩展游标批次和增量详情缓存。
- 同 Server 总 P4 进程数限制为 4，修改命令限制为 1；大文件列表通过 stdin 分批输入，不创建逐文件进程。
- Action 通过 operation ID 推送 0–100 进度并支持排队中或执行中取消；输出超过 64 MiB 自动终止。
- 系统定位/打开通过 Tauri 异步 command 的 blocking worker 执行，系统选择器或 Explorer 不会阻塞 WebView UI 线程。
- Workspace 状态由本地单层扫描和 `fstat -Op -Or`、`opened`、`resolve -n -N`、`reconcile -n`、`ignores -v -i` 聚合；主状态优先级固定为 unresolved → opened → reconcile → sync → controlled/unknown，同时保留所有正交证据。`reconcile`/`resolve` 查询均为 preview；无权威证据返回 unknown/partial，不把所有本地文件猜成 untracked。查询限制 10,000 项且不跟随 symlink/reparse point。
- 状态缓存诊断只包含 hit/miss/coalesced/evicted/invalidated、耗时和失效原因，不暴露 cache key、路径或凭据。文件 Action、CL Action、Submit、手动刷新和 Connection 切换均使用连接/Workspace/路径/查询类型范围失效；AbortSignal 通过 operation 前缀取消本次聚合的全部 P4 子命令。
- Operation Journal 不保存命令参数、stdin、密码、Ticket 内容或文件路径，只保存不可重放的动作类别、结构化结果和脱敏日志引用；异常退出后的 queued/running 记录只标记 interrupted，不自动重放。
- LogStore 在进入内存和 JSONL 文件前再次脱敏；每次启动只创建新的会话文件，日志面板不恢复历史，旧 SQLite 也不再打开。Journal 的自由字符串字段查询前也再次脱敏；诊断 bundle 在最终 JSON 序列化后再过同一安全模块。
- LogStore 当前会话内存保持 10,000 条硬上限，磁盘文件策略限制为 1–30 天、5–50 MiB；清理仅查看文件元数据，写入期按分钟节流，不占启动路径。Settings 提供打开日志文件夹、确认后删除全部日志（含旧 SQLite）；删除与写入共锁，清理后创建空文件继续记录，并广播更新各窗口。Warning/Error 只发送带 operation ID 的 `diagnostic-alert`，是否展开由前端偏好决定，不抢焦点。
- 诊断导出固定写入应用数据目录下的 `diagnostics`，使用随机文件名、临时文件完成后原子改名，失败清理临时文件；当前最小格式为 `p4deck-diagnostic-json-v1` 单 JSON 文件，128 KiB 硬上限，包含 manifest、脱敏日志与结构化操作摘要，不包含 Workspace 文件、stdin、密码、Ticket 内容或原始命令参数。压缩包格式留待确有跨工具消费需求时再评估，不调用 Shell 压缩。
- 后端性能入口 `pnpm test:perf:backend` 仅在显式 `backend-perf` feature 下编译独立 release binary，不混入普通 Rust 单测；确定性门禁覆盖 parser/domain 条目与分类、serde round-trip、TTL/LRU/并发合并/失效、cursor 错配拒绝和 Unicode 去重。项目尚未定义后端数值阈值，所有 p50/p95 均为信息项。
