    01 / 快速上手

    先准备三样东西

    1. 装 P4Deck。 去 最新 Release 的 Assets，下载 Windows x64 的 *-setup.exe 并安装。默认安装器可能需要联网补装 WebView2。公开可下载的平台以 Releases 为准。
    2. 确认电脑上有官方 P4 CLI。 在 PowerShell 运行 p4 -V。如果找不到命令，安装 Perforce 官方 P4 CLI（项目要求 2023.1 或更新版本）；再到 P4Deck 的连接设置点「重新检测 CLI」，或指定 p4.exe 路径。
    3. 向团队拿连接信息。 你需要服务器地址、P4 用户名，以及分配给你这台电脑的 Workspace 名称。已有 P4V 的话，可以在它的连接信息里核对；不确定时问管理员。
    三个词先认清。 Depot 是服务器上的版本仓库；Workspace 决定哪些仓库路径映射到哪个本地目录；Changelist（CL）是一批一起管理或提交的文件改动。
    02 / 连接设置

    把现有连接带进 P4Deck

    首次启动按引导进入「连接设置」；之后也能从「设置」打开。选择已有配置，或点「新建连接」。

    Server / P4PORT
    照抄团队给你的主机和端口。示例：ssl:p4.example.com:1666。如果团队给的地址有 ssl:，不要删掉。
    User / P4USER
    填你的 Perforce 用户名。它可能和公司邮箱或电脑登录名不同。
    Workspace / P4CLIENT
    选已分配给本机的 Workspace，并核对解析出的 Root（本地根目录）。填工作区名称，而不是目录路径。
    字符集、Tickets、Trust
    沿用已有客户端配置或团队要求；只有团队用了自定义路径时再填。不要把密码或票据内容当作路径。
    1. 点「验证这些设置」。如提示 SSL 指纹未受信，先通过团队可信渠道核对，再选「信任此精确指纹」。
    2. 如提示需要登录，使用连接设置里的「登录」。若服务器要求外部 SSO 或 MFA，按团队指定流程完成认证，再回应用重新验证。
    3. 保存连接。若未启用，点「使用此连接」。看到「已连接并登录」后，打开「工作区」，核对当前名称、Root 和文件列表。
    03 / 第一次提交

    用一个测试文件走完整流程

    选团队允许写入的测试 Workspace 和一份已纳入版本管理的文本文件。刚接触 Perforce 时，先练习单文件提交。

    1. 获取最新。 在「工作区」找到文件，右键「获取最新」，核对文件路径和版本后执行。同步完成后再编辑。
    2. 签出并修改。 右键「签出」，选择目标 Pending CL（也可用 Default）。在编辑器里改一小处并保存。
    3. 看 Diff。 右键「与 have 版本比较」。have 指当前工作区已同步的修订。确认差异只包含你刚做的修改。
    4. 提交。 进入「变更列表 → Pending」，选该文件并点「提交选中文件」。填写描述，检查文件清单和预检提示，再确认提交。
    5. 确认结果。 等操作显示完成，去 Submitted 用返回的 CL 编号核对。若状态未知，先查记录和日志，再决定是否重试。
    04 / 文件管理

    工作区、同步和对账

    • 找文件。 「工作区」看本地映射范围；「仓库」看服务器上你有权访问的 Depot。切换 Workspace 后，先确认名称、Root 和 Stream。
    • 同步最新或指定修订。 在文件或目录上右键「获取最新」；要某个历史版本，从文件历史选择修订再获取。同步目录前核对是否递归及影响范围。
    • 签出、添加、删除或还原。 在文件右键菜单选对应操作；新文件用「添加到 P4」。还原可能丢弃本地改动，确认前先看差异。锁定/解锁受服务器权限和文件类型限制。
    • 补记本地修改。 如果你在 P4 外面新增、修改或删除了文件，右键选「对账」，先看预检列出的增、改、删，再勾选想加入 CL 的文件。首次尽量对小目录操作。
    05 / 变更列表

    整理、搁置和提交

    • 整理 Pending。 展开 CL 查看文件。用右键菜单或拖放，把文件移到另一个 Pending CL；Default 是还没有分配到编号 CL 的那组改动。
    • 只提交选中的文件。 展开多个 Pending CL，勾选要交的文件，选「提交选中文件」。对跨 CL 的选择，按提示填写新的编号 CL 描述，复核清单，再提交。其他文件留在各自的 CL。
    • 先搁置再取回。 在编号 Pending CL 或所选文件上选「搁置」。Shelf 把改动副本放在服务器，方便审查或接力。打开「查看搁置内容」预览；需要应用时选「Unshelve 到 CL」，核对目标 Workspace、CL 和文件。
    • 处理冲突。 若预检提示需要 Resolve，先看涉及的文件和版本，选择适当策略，再复查差异。手工文本合并仍在验收；需要时可按团队已有的 P4V/P4Merge 流程处理。
    06 / 审查改动

    Diff、文件历史与分支

    • 看本地改了什么。 从工作区或 Pending 的文件菜单进入 Diff。对比 have 版本适合提交前检查；如需其他基线，用「与其他文件/版本比较」。
    • 找出哪次提交改的。 右键文件打开「文件历史」，点修订看对应 CL。选中两条修订后用「比较所选修订」；想了解分支间的修订关系，打开「修订图」。
    • 看 Stream 和映射。 在「分支流」查看 Stream 列表，或打开只读 Stream Graph 查看拓扑。切换 Stream 前核对当前 Workspace 和 Pending 文件。用 Branch Mapping 查看映射的源、目标与方向。
    07 / 快速定位

    找文件、CL、Stream 或 Shelf

    1. 打开「搜索」，输入文件名、Depot 路径片段或 CL 编号等线索。
    2. 选结果类型：工作区文件、仓库文件、Pending CL、Submitted CL、Stream 或 Shelf。按回车或点「搜索」。
    3. 打开匹配结果看详情。如果已知 Submitted 编号，也可以在 Submitted 中用「转到 CL」，无需重设当前筛选。
    08 / 提交记录

    从 Submitted 到周报

    1. 打开「变更列表 → Submitted」。按用户、日期、Depot 路径或 Stream 收窄范围。选多个 Stream 时，匹配其中任意一个即可。
    2. 展开 CL 查看文件与描述。若用提交类型降噪，把疑似 CI 和自动生成分类当线索；它们来自规则判断，不能证明提交者身份。
    3. 点「生成周报提示词」，选一个用户和日期区间。生成后先检查条目与 CL 引用；若界面提示部分结果，补查后再使用。提示词在本地生成，由你决定是否复制和分享。
    09 / 等待服务器时

    界面有响应时，还能做什么？

    • 先看已有数据。 等待 P4 时可以切回已打开的页面。Pending 和 Submitted 等视图会优先使用对应连接或查询的本地缓存；首次查询、缓存不存在或需要更新时仍会访问服务器。
    • 区分缓存和最新状态。 缓存可能落后于队友的修改。重新连上后，提交前用页面的刷新功能核对重要数据。完全离线时只能查看本机已有的内容，不能提交或获取新修订。
    • 区分界面反馈和确认结果。 移动 Pending 文件时，文件可能马上出现在目标 CL；这是乐观更新，后台确认后会校正。同步和提交要等实际结果；若显示失败、部分成功或未知，到操作记录核对后再处理。
    10 / 工具区

    终端、P4 Log 与操作记录

    • Terminal： 从底部工具区打开，先核对 Server、User 和 Workspace。可用 p4 info 查看上下文。它用于 P4 命令，认证操作请回连接设置。
    • P4 Log： 操作失败时从底部打开日志，按命令、级别或操作定位错误。分享诊断信息前仍要检查是否含项目路径等内部信息。
    • 操作记录： 查看正在执行、成功、失败或状态不明的任务；操作未确认完成时先查记录，避免重复提交。
    11 / 可选配置

    Windows 上的 P4VFS 虚拟工作区

    第一次用 Perforce 建议先选标准同步。若团队已经部署 P4VFS，先确认 Windows 客户端已安装 P4VFS、应用进程可读到 P4ALTSYNC，且 Server 和 P4 CLI 都支持 altsync（至少 2023.1）。

    「新建 Workspace」时选「P4VFS 虚拟同步」，保存后在 Workspace 页检查就绪状态，再照常同步。实际内容由 P4VFS 按需下载。现有标准 Workspace 不支持在 P4Deck 内原地转换。

    12 / 常见问题

    遇到问题，先查这里

    提示找不到 P4 CLI

    用 p4 -V 确认是否安装。装好后点「重新检测 CLI」，必要时重启 P4Deck 或在连接设置手动选 p4.exe。

    服务器无响应或登录过期

    确认网络或 VPN、Server 地址和 ssl: 前缀。票据过期就从连接设置重新登录；SSO/MFA 用团队规定的方式。若网络正常仍报错，到 P4 Log 找对应命令和提示。

    仓库有文件，工作区里却没有

    先确认当前 Workspace 的 Root、Stream 和映射是否包含该路径，且你有权限；映射正确也需要同步文件才能在本地磁盘看到它。

    提交被拦截，或者结果不确定

    核对描述、文件清单、权限与冲突。收到部分成功、超时或未知结果时，用返回的 CL 或操作记录核对服务器结果，再决定怎么处理剩余文件。
