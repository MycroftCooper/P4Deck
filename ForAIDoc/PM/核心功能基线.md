# P4Deck 核心功能基线

> 文档角色：长期核心能力基线；不是当前任务队列。
> 当前实现与剩余验收见 [项目状态总览](项目状态总览.md) 和 [Windows 本机私用 TODO](Windows本机私用TODO.md)。
> 原始约束：以下能力必须进入首个可用版本，不能作为后期体验优化处理。

## 一、按需 P4 命令行窗口

P4Deck 必须提供内置 P4 命令行窗口，用于高级用户直接运行 `p4` 命令和处理 GUI 尚未覆盖的场景。

### 产品行为

- 默认关闭，不占用主界面空间和启动资源。
- 用户可通过菜单、快捷键或命令面板主动打开。
- 打开后自动继承当前连接上下文，包括 Server、User、Workspace、当前目录、Charset、Trust 和 Ticket 配置。
- 命令行窗口明确显示当前上下文，避免用户在错误 Workspace 执行命令。
- 支持命令历史、复制输出、清屏、中断当前命令和重新执行。
- 可以停靠在主窗口底部，也可以独立成窗口；用户选择需要持久保存。
- GUI 发起的命令不能伪装成用户在终端输入的命令，二者在记录中必须可区分。

### 安全要求

- 禁止在命令历史和日志中记录密码、Ticket 或其他敏感标准输入。
- 用户直接输入的命令允许调用 `p4`，但不默认提供通用系统 Shell 权限。
- 终端必须使用当前已配置的 P4 CLI，不自行下载未知可执行文件。
- 通用 Terminal 不得读取、枚举或修改认证秘密：`login`、`login2`、`logout`、`trust`、`tickets`、`passwd`、`set`、`configure` 及其大小写、前导全局参数和凭据参数变体必须在创建子进程前拒绝；Trust/Login/Logout 只走 Settings 的受控认证 API。
- `-P value`、`-Pvalue`、`P4PASSWD=`、`P4TICKETS=`、认证 stdin/argument input 与继承环境不得进入通用 Runner。拒绝文案必须稳定，不回显秘密，并提供连接设置恢复入口。
- stdout、stderr 和 JSON Lines 必须在生成 `OperationEvent` 前完成上下文脱敏；`OperationResult`、Terminal 输出/历史、P4 Log 内存与 SQLite、Operation Journal、诊断导出和错误文本只能接收脱敏副本。禁止“先广播原文、落盘前再脱敏”。
- 脱敏至少识别 Ticket/password/passwd/P4PASSWD/P4TICKETS、Authorization/Bearer、显式已知 secret 及多行标签值；普通裸 32 位十六进制 digest 不得被全局误删。

## 二、按需 P4 日志窗口

P4Deck 必须提供独立的 P4 Log 窗口，集中展示应用调用 P4 CLI 的过程、服务器消息、警告、错误和耗时。

### 默认状态与未读错误提示

- 默认关闭，不干扰正常工作。
- 普通成功命令只写入日志，不自动展开。
- Warning、Error 和操作完成后的 warning 都只写日志，不得自动展开、切换 Terminal/Journal、设置 operation filter 或抢夺焦点；旧版已保存的自动展开偏好也不再生效。
- 未查看的新 Error 只在底部日志入口显示红点，并提供非颜色的可访问名称；Info/Warning 不产生红点，用户查看日志后清除。
- 相同 operation/级别的诊断事件去重，避免未读提示抖动或消息洪水。
- 用户可通过底部工具区、快捷键或命令面板随时手动打开；Terminal/P4 Log 不在左侧 Activity Bar 重复显示。

### 日志能力

- 按时间、级别、Workspace、P4 命令、操作类型和关键词筛选。
- 每条记录关联操作 ID，可从 UI 操作跳转日志，也可从日志返回对应操作。
- 支持复制单条、复制脱敏命令、导出诊断包和清空当前视图。
- 默认日志必须脱敏密码、Ticket、认证输入和敏感环境变量。
- 启动读取旧日志时必须在查询/导出边界再次脱敏；当前实现还会以事务方式原地清洗旧行并压缩数据库，失败时不删除数据库且读侧脱敏继续兜底。
- 日志采用有上限的环形缓冲与分段落盘，不能因长时间运行无限占用内存或磁盘。

## 三、完整 Changelist 工作流与强制虚拟列表

Changelist 是 P4Deck 的核心对象，首个可用版本必须覆盖日常 CL 操作，而不是只支持 Submit。

### CL 操作

- 查看 Default、Pending、Submitted 和 Shelved Changelist。
- 创建、编辑、删除 Pending CL。
- 修改 Description、Jobs、文件列表和必要的 Submit 选项。
- 通过多选、拖放和命令将文件移动到其他 CL。
- 支持把文件移回 Default CL。
- 支持 Shelve、更新 Shelf、删除 Shelf、Unshelve 和预览 Shelf 内容。
- Submit 前校验 unresolved、out-of-date、锁、权限和空描述等问题。
- 操作完成后增量更新受影响 CL，避免全量刷新。

### 性能红线

- CL 列表、CL 文件列表、Depot 文件、历史、日志和搜索结果从第一次实现起就必须使用虚拟列表或等价的窗口化渲染。
- 禁止先实现全量 DOM 列表、以后再优化。
- 数据获取采用分页、游标或流式批次；禁止等待全部记录后一次性渲染。
- 排序、筛选和搜索不能阻塞 UI 主线程。
- 大列表的选择状态必须按稳定 ID 管理，不能依赖当前渲染行索引。
- 在 100,000 条模拟记录下持续滚动不得出现明显卡顿。
- 50,000 条记录的本地筛选反馈目标小于 50 毫秒。

## 四、Changelist 查询、过滤与降噪

CL 查询必须支持多个条件组合，不允许只提供一个简单关键词框。

### 基础过滤条件

- 关键词：Change ID、Description、User、Client、文件路径和 Job。
- 状态：Pending、Submitted、Shelved、Empty、Unresolved。
- 用户：本人、指定用户、多个用户。
- Workspace/Client。
- Stream、Depot Path 或文件路径范围。
- 时间范围：今天、最近 7/30/90 天、自定义起止时间。
- 是否包含文件、是否包含 Shelf、是否有 Job。
- 支持多个条件组合，并清晰展示当前已启用条件。

### 分支合并 CL 降噪

- 提供“隐藏分支合并/集成 CL”开关，默认状态由用户设置决定。
- 不能只依赖 Description 文本判断，应综合 Integration 记录、文件 Action、Stream/Branch 信息和可用的服务器元数据。
- 无法可靠判断时标为“疑似合并”，而不是直接隐藏。
- 用户可以随时查看被隐藏的数量，并一键恢复显示。
- 支持保存过滤器，例如“我的代码提交”“最近 7 天非合并 CL”“当前 Stream 的 Shelves”。

### 查询体验与性能

- 支持服务端过滤的条件优先下推给 P4 CLI，减少传输和本地计算。
- 需要本地二次判断的条件采用后台增量处理，并允许取消。
- 新查询必须取消或淘汰已经过时的查询结果，避免旧结果覆盖新条件。
- 结果列表使用虚拟化和增量加载。
- 查询条件应写入 URL 等价的内部状态，便于恢复、收藏和复制为诊断信息。
- Submitted 分页必须使用稳定 keyset cursor；cursor 需版本化并绑定完整查询条件、Connection identity 与 generation。结果契约明确返回 `items`、`nextCursor`、`hasMore` 与扫描/匹配/隐藏/截断统计；禁止裸 offset。
- P4 不能直接表达的 Job、部分 Stream 或 merge 过滤必须采用有界批次与集合交集，允许取消并显式报告安全上限截断；禁止每条结果无上限执行 `describe`/`filelog`。
- Pending 的 Default CL 不是 numbered 分页中的伪编号：协议必须把它作为独立固定对象返回，前端始终置顶且只保留一个实例。numbered CL 采用稳定快照 cursor；cursor 绑定规范化 filter/sort/page size、Server/User/Client、Connection generation、Pending data generation 与随机 snapshot identity，服务端只接受实际签发的 continuation。
- Pending 首次快照也必须有硬上限。当前实现最多扫描 500 个 numbered CL 和 100,000 个 opened file 记录；触顶返回 `partial/truncated/stats`，不得继续无界拉取。创建、编辑、删除、Submit、Shelf、Unshelve、Move 会递增 Pending data generation 并废弃旧 cursor 链，避免重复、漏项或幽灵卡片。

## 五、首版验收场景

1. 用户在当前 Workspace 中手动打开 P4 命令行，执行 `p4 opened`，中断一个长命令后关闭窗口，主界面不受影响。
2. GUI 执行命令、Warning 或 Error 到达时日志窗口保持原状态且不切换当前工具；未查看 Error 只点亮底部日志红点，手动查看后清除，并能定位到脱敏记录。
3. 加载 100,000 个 CL 文件，持续滚动、选择和移动文件时界面保持响应。
4. 将多个文件从 Default CL 移到 Pending CL，Shelve 后再 Unshelve 到另一个 Workspace。
5. 查询最近 30 天当前用户的 Submitted CL，以路径和关键词筛选，并隐藏可靠识别的分支合并 CL。
6. 切换过滤器时，旧查询被取消，界面不会短暂显示错误结果。
## 对象驱动产品模型

P4Deck 不按底层命令组织界面，而按用户当前处理的对象组织：

| 对象 | 核心视图 | 核心动作 |
|---|---|---|
| File | Workspace、Depot、Diff、History、Revision Graph | Sync、Get Revision、Checkout、Add、Delete、Revert、移动到 CL |
| Pending CL | Default/Pending、Opened Files、Shelved Files、Jobs、Resolve | 新建、编辑、删除、移动文件、Shelve、Submit |
| Submitted CL | 查询结果、详情、文件、Integration | 搜索、过滤、合并降噪、Diff、Sync 到版本 |
| 全局搜索 | Submitted/Pending CL、Workspace/Depot 文件、Job | 分组结果、稳定 identity、导航目标、匹配字段/高亮、facet、稳定分页、partial/错误状态；Stream/Shelf 待独立立项 |
| Shelf | Shelf 文件、预览、风险 | 创建、更新、部分/全部删除、Unshelve |
| Workspace | Client Root、View、Stream、本地/P4 状态 | 切换、刷新、Sync、Reconcile |
| Depot | 服务器目录、版本、映射 | 浏览、定位到 Workspace、Sync、History |
| Stream | Stream 与集成关系 | 查看、切换 Workspace；完整编辑后续实现 |

全局操作逻辑固定为“选择对象 → 查看状态 → 执行动作 → 查看结果/日志”。工具栏和右键菜单必须复用同一命令注册表。

## 独立工作流

- Pending：只显示当前用户+当前 Workspace；文件可在 Default/Pending CL 间拖放或右键移动；Shelf 是 CL 内独立区域；Submit 必须经过校验。
- Submitted：只显示已提交记录；默认最近 30 天；搜索、用户/Client/路径/时间/Job 过滤和合并降噪只属于本页。
- Shelf：预览后创建/更新/删除；Unshelve 必须先预览，遇到覆盖、锁、权限或 Resolve 风险进入确认流程。
