# 前端架构与维护约定

本阶段整理保留现有页签、目标锁定、分屏、弹出、边栏和主题交互，不更换 UI 框架，也不扩大 P4 操作范围。原有持久化键及页签 ID 格式保持兼容。

## 分层与职责

```text
src/
  app/
    App.tsx                 工作台装配：连接、选择对象、布局、工具区
    panels.ts               页签唯一元数据源：类型、名称、多开规则、目标来源
    PageRenderer.tsx        类型到业务组件的穷尽映射、按需加载、错误隔离
    shell/                  顶栏、活动栏、对象工具栏、状态栏及独立的偏好控件
    hooks/                  偏好设置、连接生命周期、URL/页签导航
    docking/                Dockview 适配、目标锁定、独立窗口、布局保存
    dialogs/                模态基础、虚拟目标清单、预检状态、异步请求协调
    styles/                 主题变量、Dockview 适配、共享布局及功能样式
  features/
    files/                  文件列表、侧栏、共享查询、文件操作策略
    browsers/               History / Streams / Diff / Rev Graph / Preview
      useFilePreview.ts     预览读取、缓存、防抖、过期结果隔离
    changelists/            Pending / Submitted；查询状态属于对应页面
    settings/              设置表单、可验证的偏好模型
    tools/                 命令行/日志状态、订阅、历史记录校验
    workspaces/            工作区列表
    search/                单例搜索页 UI、文件/CL Tab、纯 CL 编号校验（尚未接入查询）
  infrastructure/backend/  Mock / Tauri 的统一类型化接口
  shared/
    contracts/             后端交互数据类型（不再重复定义 AppRoute）
    i18n/                  公共文案
    lib/                   安全存储、延迟保存、异步订阅生命周期等基础工具
```

依赖方向：工作台装配功能页面；页面使用 Backend 契约，不自行拼接 IPC 或执行进程。Dockview 的实例对象不进入业务页面。页签向页面传递目标字符串、锁定状态与目标修改回调。

## 状态归属

- App 负责装配；useWorkspaceSelection 统一持有选择集合、主目标和当前目录，并协调 useCommandTarget。不要再添加并行的 onSelect props 通道。
- selectionState.reconcileSelection 是纯函数：异步补全仅更新仍被选中的同一批路径，不能把新的选择或清空状态覆盖掉；无变化时保留状态引用。
- SelectionContext 是三个文件列表的唯一选择入口；Provider 值与命令转发回调保持稳定。
- usePreferences 管理主题、语言、密度、字号和跨窗口同步；设置页只编辑它，不反向成为 App 的状态仓库。
- useRuntime 处理连接初始化与更新；初始化返回晚于连接更新时不会覆盖新连接。
- Dockview 是页签实例与活动组的事实来源。panels.ts 仅负责纯策略，不再保留另一套 afterClose 邻居选择算法。
- SubmittedPage 自己拥有筛选、稳定查询快照、opaque cursor 与累计 stats；连接/筛选变化和卸载都会取消旧 operation、清空旧页并使旧响应失效。分页错误保留已有结果与 cursor 供重试，详情选择只在仍存在的行上生效。保存过滤器经版本化白名单 schema 写入本地 Storage，不持久化连接 Context、cursor 或凭据。
- PendingPage 自己拥有版本化本地 filter/sort、request generation、operation cancel、cursor 链和累计实体集合。Default 只从 `defaultChange` 接收并排在首位；numbered 页按 change ID 去重。筛选、排序、连接或刷新变化必须取消旧 operation、清空旧 cursor 链；创建/编辑/删除/Submit/Shelf/Unshelve/Move 后只允许先按稳定 ID 合并反馈，再启动新的第一页，禁止继续消费写前 cursor。
- ToolArea 拥有日志及操作事件。事件频繁到达时不会逐条更新 App 的状态；通过窄的命令接口打开工具区或刷新日志。
- FilePreviewPage 负责呈现；useFilePreview 负责异步数据，已有读取限制与缓存策略保持不变。

## 性能与可靠性

1. 业务页通过 React.lazy / Suspense 按需加载。默认文件列表保持直接加载，错误边界限定在单个页签内。
2. 文件侧栏与文件主列表使用同一个 QueryClient 和连接隔离的 query key；`workspaceQuery` 消费完整 `WorkspaceListing`，并发请求去重、短期缓存和刷新结果共享。每次请求生成 operation 前缀，AbortSignal 取消整组后端子命令；手动刷新显式传 `refresh=true`，不能只失效 React Query。Depot 未选中、资源侧栏折叠时不主动加载其查询；展开仍复用缓存，不清空筛选和选择。
3. 拖动分隔线引起的布局保存合并为 120ms 延迟写入；pagehide 时冲刷。页签类型集合不变时，不重复通知 App。
4. 保留虚拟列表和预览文件大小限制。P4 进度来自事件，100ms 合并渲染、不保存输出历史；磁盘容量仅在桌面版通过本地 IPC 每分钟刷新，后台窗口暂停定时刷新，不访问 P4。
5. Pending 顶层卡片和卡内文件使用两层独立 TanStack Virtual。顶层按 change ID 提供 `getItemKey`、动态 `measureElement` 与 overscan；展开状态、选择、焦点目标、拖放来源/目标均保存稳定 ID，不保存 virtual index。Default 折叠卡常驻 range 并 sticky；展开高行参与测量。原生拖放只接受当前挂载目标，滚动负责挂载后续目标；键盘/右键 Move 对话框可直接输入离屏 CL ID，并由后端预检确认。
6. subscribeSafely 处理“组件先卸载、监听注册后完成”的竞态，避免泄漏监听。
7. 偏好与布局存储失败不应令 UI 崩溃；损坏的页签目标、终端历史和高度进行校验。
8. 工具栏与右键菜单复用 commandPolicy 能力判断和 CommandExecutionContext 执行入口；selectionCommands 负责批量去重及目录递归文件规格。
9. 样式清理了 181 条被后续相同选择器覆盖的声明；保持必要的层叠顺序，避免为了分文件重排交互样式。主题变量独立维护。
9. 启用 TypeScript 未使用变量/参数检查，以及 Prettier 格式检查，防止重新堆积超长行和废弃代码。
10. 活动栏使用 panels.ts 派生的 activityPageIds，仅包含全局页面；设置独立固定在底部。旧下拉菜单逻辑及其样式已删除，不维护第二份入口可见性列表。
11. AppControls 只处理底部语言/主题控件，与 TopBar 分离；status.css 维护状态栏样式，避免继续往 commands.css 追加无关样式。顶部连接灯读取实际连接状态，演示模式在提示中明确标注。
12. 搜索文件与搜索 CL 切换时清除示例结果和结果选中项，分别保留输入草稿；CL 模式不能通过任意关键词提交。
13. Workspace 行只依据 `WorkspaceFileStatus` 展示可组合角标：opened/move、modified/missing、out-of-date/not-synced、unresolved、ignored provenance、symlink 与 partial/error/unknown。列表级 partial/error 必须保持可见，title/读屏文本包含全部 evidence；目录不得推断子项状态，也不得为每行额外请求。Files/Depot 继续窗口化，不把最多 10,000 项完整挂入 DOM。

这些是可验证的结构和请求次数改进，不代表已经测得真实 P4 环境的 CPU/内存降幅。大量文件、慢服务器及 Windows/macOS 原生多窗口仍需专项性能和实机验收。

## 操作弹窗的组织与维护

- `Dialog` 只管呈现与交互基础：来源 document、原生模态、初始焦点、键盘循环、关闭/回焦、滚动与忙碌。它不知道 P4 命令，也不读取业务目标。
- `useDialogRequest` 管理异步请求的生命周期；`useCommandDialogs` 用判别联合协调命令弹窗，保证同一 App 实例只能打开一个命令弹窗。CommandBar 只负责能力判断、构造目标快照、等待确认与调用已有执行契约，不再维护六套弹窗状态。
- 业务表单位于 `features/changelists/components` 和 `features/files/components`。`TargetList`、`PreflightStatus` 和危险范围确认复用基础组件；表单校验不冒充服务器预检。
- `FileClWorkflow` 是文件入口到 CL 操作的适配层：显式打开时读取 Pending，验证所有文件归属；跨 CL 先明确分组或跳过项，再复用同一 Move/Shelf 表单，不静默缩小操作范围。
- 工具栏、菜单和页面按钮应复用流程/菜单工厂。菜单将原始触发元素贯穿传递给弹窗，不能用主窗口的 activeElement 猜来源。跨 document 测试并不替代原生 Win/mac 验收。
- 异步数据必须按连接隔离；关闭、卸载和连接变更取消旧请求。真实操作结果由 `fileActionFeedback` 解释：非零退出码、取消与错误不能显示成功，异常可能已部分执行，不承诺回滚。
- 新增真实执行适配器时保留预检身份、有效期及完整范围验证。UI-only 流程继续明确显示“不执行”；不要为了让按钮能点就绕过缺失的预检。
- `?workflow-audit` 仅开发模式加载，提供无服务器调用的表单/虚拟列表合成场景。`testHarness` 是新对话框测试的公共基础；布局实测、行为单测与原生验收各自记录，不互相替代。

## 新增页签的流程

1. 在 app/panels.ts 增加元数据：中英文名称、global/file、local/depot 目标来源。
2. 在 features 对应领域实现组件；需要访问数据时使用 Backend 接口。
3. 在 PageRenderer 加入按需加载与 switch 分支。新增类型若遗漏分支，穷尽检查会报错。
   全局页面会自动进入 activityPageIds，需要同时补充 ActivityBar 的图标映射；类型检查会检查遗漏。
4. 文件页签使用传入的 target / locked / onTargetChange，不另建一套全局选中文件状态或自己写布局存储。
5. 若增加原生弹出页签类型，更新 Rust open_panel_window 的允许列表。该列表是跨进程安全边界，不与 UI 注册表强行共用运行时代码。
6. 将页面样式放在对应样式文件，通过 styles.css 有序引入；不要在文件末尾反复补同选择器覆盖。
7. 添加策略/数据测试，再验收关闭、多开、锁定、主题、布局恢复和错误状态。

## 验证

```bash
pnpm format:check

```

已有自动测试涵盖单/多实例路由、目标复用、锁定目标、损坏存储、异步监听卸载、布局写入合并、连接隔离及共享列表查询去重。浏览器验证覆盖保存布局恢复、设置单实例、亮暗主题、预览图像和工具区折叠；原生跨窗口行为不可仅凭浏览器测试宣称通过。

## 本轮整理后的待验收边界

- 搜索仍是 UI-only：示例有明确标识，不伪装服务端结果；下一阶段单独接入实际文件查询、CL 查询与结果定位。
- 顶部工作区按钮目前是连接设置入口，并非真正的多连接/工作区切换下拉；需要后续确定连接配置管理流程。
- 桌面原生弹出/返回、窗口关闭、磁盘容量，以及 Windows/macOS 系统打开行为，需要双平台实机验收。
- 当前并发 P4 进度是已知任务百分比的算术平均，不是整体剩余时间估算；任务没有可量化进度时显示不确定进度。
- 现有共享 workbench.css 仍较大。本轮只删除确认无引用的旧菜单/页签 CSS，不做未覆盖业务页面的大规模视觉改写。
