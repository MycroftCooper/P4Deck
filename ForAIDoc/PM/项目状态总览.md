## 1. PM 结论

P4Deck 已经越过“只有原型和 Mock”的项目启动阶段：桌面端真实 Backend、受控 P4 Runner、Workspace/Depot 浏览、基础文件操作、文件预览、Diff/History/Revision Graph、CL 查询及部分 CL/Shelf 命令都已有代码落点，应用壳、Dock 布局、主题和中英文界面也已成形。

当前仍属于 Alpha 工程阶段，主要原因如下：

1. 连接与认证已形成版本化多 profile 前后端闭环：设置页 CRUD/重命名/危险删除确认、活动切换、revision 冲突恢复、草稿认证边界及 Workspace 两阶段真切换均已接生产契约；旧单 Context 原子迁移/备份、generation/cancel/cache 隔离和 Windows localhost 双轮验证已落地。真实 SSL Trust、SSO/MFA、过期 ticket、成功 Server 切换和 Windows/macOS 原生 UI 仍待实测。
2. 单文件 Rename/Move、Submit、Pending 菜单/键盘/拖放移动、独立 Shelf 详情/内容预览及 Shelf/Unshelve/Resolve 已完成 BE-002R/BE-003/BE-004a/BE-004b 前端生产接线和浏览器自动化验收；Shelf 详情已从 offset 改为绑定 profile/Connection/双 generation/query 的服务端冻结快照 cursor，含重放拒绝、结构化失效和旧响应隔离，Rust 独立窗口白名单也已补齐。后端真实闭环与 Windows localhost 连续双轮 E2E 已完成，但 Windows/macOS 原生 UI 仍待验收。Rename/Move 仍明确不支持目录、跨 Workspace、覆盖和 Windows 仅大小写改名。
3. BE-005 Workspace 状态已把单层本地扫描与 `fstat/opened/resolve preview/reconcile preview/ignores` 聚合成强类型契约；前端组合角标、证据、partial/error、共享查询、手动刷新和分组取消已接通。Windows localhost 已覆盖主要状态，macOS/P4 版本矩阵与原生窗口读屏仍未验收。缓存指标、Operation Journal、P4 Log 策略与诊断导出也已完成生产接线；BE-007S 已把凭据策略前移到事件广播前并覆盖历史、SQLite、Journal 与导出末端。
4. BE-010/FE-20 基础 Stream 切换已完成：Streams 页提供默认不改文件的仅视图切换和显式可选同步；后端使用一次性全身份/digest token、mutation lane 复检、非 force `client -s -S`、最终 Client spec 验证与结构化恢复。Windows localhost 两条真实 Stream 已覆盖切换/恢复/回切；原生双平台 UI 与 macOS/多版本 P4 仍待验收。
5. BE-011/FE-21 文件 Lock/Unlock 已完成生产闭环：工具栏、原生菜单及 F01/F02/F07/C04/C05 统一进入预检；完整文件集、opened action/CL、filetype/`+l`、权限与锁 owner 绑定一次性 token，mutation lane 内 TOCTOU 复检并逐文件验证。Workspace/Pending 已显示我方/他方锁和独占角标；Windows localhost 双用户/双 Client 已覆盖冲突、解锁、重放与漂移，原生双平台 UI 与 macOS/多版本 P4 仍待验收。
4. Pending 顶层 CL 卡片与卡内文件、Global Search、P4 Log 与 Operation Journal 的全量 DOM 缺口已窗口化；Pending 后端已改为 Default 独立对象 + numbered 稳定快照分页，并具有取消、双 generation、partial/truncated 与有界扫描。50,000 条 Pending 组合筛选和 100,000 条顶层/文件双层虚拟 DOM 门禁已加入；Windows/macOS 固定设备的原生持续滚动/FPS、内存峰值和读屏仍无验收记录。
5. Terminal / P4 Log 已从底部工具区扩展为可发现、可停靠/独立窗口、可恢复的全局 panel：应用菜单、命令面板、活动栏和统一快捷键已接入；profile/generation 变化会取消并隔离旧 Terminal 结果，通用窗口 placement 支持多屏越界回落。Windows/macOS 原生菜单、位置/大小、焦点、快捷键和读屏仍待实测。
6. 全应用统一 action 目录共 37 项，覆盖全部现有 `CommandBar` 主操作、连接/Profile、页面、Diagnostics、设置与窗口入口，并与 Rust 原生菜单 37 项自动校验；mutation 只映射回既有状态机。菜单注册表共 503 leaves，排除 U07 后为 502 个自定义项；190 个 `phase: later` 项保持延期。幂等只读 retry、活动页自动刷新、状态栏暂停/恢复/失败/上次更新时间，以及带前台抑制、去重和脱敏的桌面通知适配层已落地。Windows/macOS 原生菜单、系统通知、焦点与读屏仍待实测。
7. 本地仓库已有经验证的阶段提交与 `ci:quick` / `ci:local` 统一门禁；手工触发、只读、不发布的三平台远端 CI 配置样板也已入库。但项目仍无 remote，样板从未在远端 runner 执行，不能视为异机可恢复或可发布基线。

因此，当前里程碑仍不应标记为“可供私有 Alpha 使用”。生产构建、BE-002～BE-004b 及 BE-008 前后端基线已恢复绿色；下一目标是完成原生流程冒烟，并建立 remote/CI。

## 2. 状态口径

| 状态 | 定义 |
|---|---|
| 已完成 | 有前后端或明确单端实现，并有自动化测试或可重复验证证据；在当前约定范围内可用 |
| 部分完成 | 已有 UI、契约或底层能力，但用户流程、异常处理、平台验证或验收证据不完整 |
| 未开始/未完成 | 没有可用实现，或只有文档规划、占位入口 |
| 阻塞 | 会阻止构建、集成、验收或发布的问题 |

功能是否“完成”以用户闭环和验收证据为准，不以文件、按钮或接口是否存在为准。

## 6. 当前项目结构与职责

```text
P4Deck/
├── src/                         React 前端
│   ├── app/                     应用装配、Dock、Shell、全局 Hook 与样式
│   ├── features/                按业务能力组织的页面和交互
│   │   ├── browsers/            Preview、Diff、History、Revision Graph、Streams
│   │   ├── changelists/         Pending 与 Submitted 工作流
│   │   ├── files/               Workspace/Depot 浏览、地址、文件动作
│   │   ├── settings/            连接、主题、语言与 UI 偏好
│   │   ├── tools/               P4 Terminal 与 Log
│   │   └── workspaces/          Workspace 列表与详情
│   ├── infrastructure/backend/  Backend 契约及 Mock/Tauri 适配器
│   └── shared/                  共享类型、i18n 和无业务归属工具
├── src-tauri/src/               Rust 桌面后端
│   ├── ipc/                     Tauri Command 边界
│   ├── app/                     应用服务与用例编排
│   ├── domain/                  领域模型
│   ├── p4/                      P4 Runner、Context 与业务 Repository/Parser
│   └── persistence/             SQLite 日志等本地持久化
├── ForAIDoc/
│   ├── PM/                      范围、路线图、状态与验收口径
│   ├── Coder/                   架构、实现说明与开发环境
│   └── Designer/                体验与界面规范
├── scripts/                     环境检查、安装辅助和本地 p4d Fixture
├── assets/                      品牌源素材
└── public/                      Web/Tauri 静态资源
```

### 结构治理规则

1. PM 文档定义“为什么做、做什么、优先级、完成标准”；技术文档定义“怎么做”；设计文档定义“如何交互与呈现”。
2. 新业务能力优先进入 `src/features/<domain>`；跨功能契约进入 `shared/contracts`；外部系统适配只进入 `infrastructure`。
3. Rust 的业务参数构造和解析放在 `p4/<domain>`；`ipc` 不承载业务规则，`runner` 不认识具体业务对象。
4. 功能状态变化先更新本文件，再同步路线图、实现说明和 README，避免多个“当前状态”互相冲突。
5. 完成项必须附验证证据；只有 Mock 演示、只有 UI 或只有底层命令时，一律记为“部分完成”。

## 8. 风险与待决策

| 风险/决策 | 影响 | 当前建议 |
|---|---|---|
| 只有本地 Git 基线、没有 remote 执行 | 本机可回滚、可运行本地门禁，但无法证明异机恢复与平台持续集成 | 需要时再建立私有 remote，并在 Windows/macOS runner 人工验证现有 CI 样板；当前不得写成已通过 |
| 文档描述曾领先/落后于代码 | 进度判断失真 | 本文作为状态单一入口，其他文档只保留稳定规范 |
| 功能面铺得较宽，核心闭环仍有缺口 | 容易出现“页面很多但不可日用” | 暂停新增 P2 页面，优先连接与 Submit 闭环 |
| P4 版本、服务器策略和平台差异 | Mock/单测通过不等于真实可用 | 建立版本矩阵与 localhost Fixture E2E |
| 本机性能基准尚未升级为双平台/多版本认证 | 单机合成数据不能证明原生滚动、精确峰值内存、P4 输出兼容性与平台一致性 | 固定 Windows/macOS 设备并留存原生 FPS、内存、读屏、P4/Unicode 矩阵与长时间运行记录 |
| 原生多窗口复杂度较高 | 可能拖慢核心流程交付 | 首个 Alpha 以稳定停靠为主，原生拖出按验收结果收敛 |
