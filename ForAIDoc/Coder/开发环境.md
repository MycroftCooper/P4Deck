# P4Deck 开发环境与新设备部署

> 文档编码：UTF-8  
> 原则：先检查、后安装；不覆盖已有的不兼容环境。

## 版本基线

| 工具 | 项目版本 | 固定位置 |
|---|---:|---|
| Node.js | 24.16.0 / 兼容 24.x | `.node-version`、`package.json#engines` |
| pnpm | 11.19.0 / 兼容 11.x | `package.json#packageManager`、`package.json#engines` |
| Rust | 1.97.1 | `rust-toolchain.toml` |
| P4 CLI | 2023.1 或更高，推荐 2026.1 | 初始化脚本 |
| Tauri | 2.x | `package.json`、`Cargo.lock` |

## 最快部署流程

克隆项目后，在项目根目录运行对应平台的初始化脚本。

环境首次配置完成后，项目根目录提供以下快速启动器。执行前先按 [本地假 P4 安全核验](本地假P4安全核验.md) 确认当前允许的模式：

- macOS：`P4Deck-Dev.command`
- Windows：`P4Deck-Dev.cmd`

两个启动器默认进入真实 Tauri 桌面开发模式（端口 1422），不是浏览器 Mock。浏览器预览须显式传入 `browser`（端口 1420）；`qa` 参数（Windows 与 macOS 都支持）先启动本地 p4 fixture，再用 QA 配置启动独立标识的桌面应用（前端端口 1423；默认与普通 dev 共用 `src-tauri/target` 以复用依赖，二者不要同时运行，确需并行时设置 `P4DECK_QA_TARGET_DIR`）。启动器在端口被上次残留进程占用时会给出提示。QA 标识本身不限制服务器地址，不能作为允许连接的证明。启动器只会在项目依赖缺失时执行锁文件安装，不会重新安装或覆盖 Node.js、pnpm、Rust、P4 等系统开发工具。

### macOS

```bash
# 先做纯检查：不会安装，也不会修改任何文件
./scripts/setup-macos.sh --check

# 默认安全模式：只对缺失组件逐项询问
./scripts/setup-macos.sh

# 新设备无人值守模式：自动安装缺失项
# 已有但不兼容的工具仍然不会被覆盖
./scripts/setup-macos.sh --yes
```

打开新终端后执行：

```bash
./scripts/doctor.sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm dev          # 浏览器 Mock，端口 1420
pnpm dev:desktop  # Tauri 桌面开发，端口 1422
```

仅做前端 Mock 开发时，macOS 也可以使用 `./scripts/doctor.sh --frontend-only`，并执行 `pnpm test:web` 与 `pnpm check:web`。

### Windows 11 x64

使用普通 PowerShell 即可。安装 Visual Studio Build Tools 时系统可能显示权限确认。

```powershell
# 只检查
.\scripts\setup-windows.ps1 -Check

# 缺失项逐项询问
.\scripts\setup-windows.ps1

# 自动安装缺失项，不覆盖不兼容版本
.\scripts\setup-windows.ps1 -Yes
```

打开新 PowerShell 后执行：

```powershell
.\scripts\doctor.ps1
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm dev          # 浏览器 Mock，端口 1420
pnpm dev:desktop  # Tauri 桌面开发，端口 1422
```

如果当前 Windows 机器只做浏览器 Mock 和前端开发，可先不安装 Rust/C++ 工具链：

```powershell
.\scripts\doctor.ps1 -FrontendOnly
pnpm install --frozen-lockfile
pnpm build
pnpm test:web
pnpm check:web
```

`-FrontendOnly` 不代表 Tauri 环境通过；`pnpm tauri dev`、Rust 测试与桌面打包仍必须补齐 Rust 1.97.1、MSVC C++ 工具链和 Windows SDK。

## 构建与打包入口

- `pnpm build`（`node scripts/build-frontend.mjs`）是浏览器构建，包含 Mock backend，用于 Web 预览。
- `pnpm build:desktop`（`--mode desktop`）是桌面构建，通过 Vite define `__P4DECK_DESKTOP__` 在编译期移除 Mock backend；`src-tauri/tauri.conf.json` 的 `beforeBuildCommand` 使用的就是它。
- `pnpm build:desktop:win`（`node scripts/build-desktop.mjs`）产出独立 exe 到 `artifacts/desktop/`，并写 `artifact-info.json`；它不是安装包，不能作为体验包交付。
- `pnpm package:desktop:win`（`node scripts/package-desktop.mjs`）产出 NSIS 安装包到 `artifacts/delivery/P4Deck-<version>-<commit7>/`。默认使用 WebView2 `downloadBootstrapper`（安装时需要联网、包体小）；传 `--offline-webview2` 改用离线安装器。该入口仅支持 Windows。
- 构建与打包入口都会先运行 `pnpm validate:versions` 校验 `package.json`、`tauri.conf.json`、`Cargo.toml` 三处版本一致，并默认拒绝脏工作树；确需时显式加 `--allow-dirty`，该标记会写入 `artifact-info.json`。
- 本机验证优先用 `pnpm ci:quick`：默认 Web 组与 Rust 组并行、失败不中断，一次跑完再给出失败摘要；只改打包或前端 mock 相关时可用 `pnpm ci:bundle`（约 10 秒，版本一致性 + `build:desktop` + `validate:bundle`，不替代交付前门禁）；需要构建、包审计和性能门禁时用 `pnpm ci:local`（默认遇错即停）。排查失败时给 `ci:quick` 加 `--verbose` 直接看子进程完整输出；完整日志在 `artifacts/ci/logs/<mode>/<step>.log`。完整说明见[本地门禁与发布配置](本地门禁与发布配置.md)与[Windows体验包交付](Windows体验包交付.md)。

## 初始化脚本的安全行为

### 已安装且兼容

脚本只打印检测结果并跳过，不重新下载、不重新安装、不修改 PATH。

### 已安装但不兼容

脚本打印当前版本和项目要求，然后以失败状态退出。它不会卸载、升级、降级或覆盖现有工具，需要开发者自行决定使用版本管理器还是调整系统环境。

### 完全缺失

- 默认模式逐项询问。
- `--yes` / `-Yes` 只自动安装缺失项。
- `--check` / `-Check` 绝不执行安装。
- Node.js 和 P4 CLI 下载后必须通过官方 SHA-256 清单验证。
- macOS 工具安装在 `~/.local`、`~/.cargo` 和 `~/.rustup`，无需 sudo。
- Windows 工具安装在 `%LOCALAPPDATA%\P4Deck` 和 `%USERPROFILE%\.cargo`。
- PATH 只追加不存在的路径，不替换原 PATH；macOS 使用带标记的配置块且只追加一次。

## macOS 详细要求

支持 macOS 13+、Apple Silicon 和 Intel。必须安装 Xcode Command Line Tools：

```bash
xcode-select --install
```

初始化脚本会检查该组件；如果缺失，只负责打开 Apple 系统安装程序，需要等待安装完成后重新执行脚本。

正式发行还需要 Developer ID Application 证书、Hardened Runtime、Apple Notarization 和 CI 签名配置，本地开发不需要。

## Windows 详细要求

当前开发基线为 Windows 11 x64，需要：

- Visual Studio 2022 Build Tools。
- `Desktop development with C++` / `Microsoft.VisualStudio.Workload.VCTools`。
- Microsoft Edge WebView2 Runtime。
- Rust MSVC Toolchain。

初始化脚本会通过 `vswhere.exe` 判断 C++ Build Tools 是否真实存在，而不仅是检查 Visual Studio 文件夹。Windows ARM64 待 CI、签名和依赖验证后纳入。

从 macOS 更换到全新 Windows 开发机时，不要直接复制 `node_modules`、`src-tauri/target`、`dist` 或 `.local`。源码保存、凭据迁移、Windows 全量构建和原生冒烟的逐步清单见 [Windows 迁移与环境恢复手册](Windows迁移与环境恢复.md)。

## 检查与故障定位

初始化脚本用于安装前审计和按需安装；doctor 用于最终验收：

```bash
# macOS
./scripts/doctor.sh

# Windows
.\scripts\doctor.ps1
```

如果脚本提示“等待 PATH 生效”，请先打开一个全新的终端，不要反复运行安装。

如果已有 Node.js 或 pnpm 版本不兼容，推荐使用已有的版本管理器切换到 `.node-version` 指定版本，不建议删除系统级安装。当前基线已在 Node 24 + pnpm 11 下维护。

## 一次性本地 p4d Fixture

浏览器视觉开发使用类型一致的 Mock Backend，不连接任何 Server。真实集成测试只允许使用一次性本地 `p4d`。`pnpm dev:desktop:qa` 会自动按平台执行 fixture start，并在退出时执行 fixture stop；手动运行下方命令时不要再与它同时占用同一个 `16661` 端口。

### Windows

Windows 使用项目内的便携式 P4 2026.1 工具链，不安装 Windows 服务、不修改系统 PATH，也不复用工作环境的 P4 配置或凭据：

```powershell
# 首次下载；固定官方 HTTPS 地址，同时校验 SHA-256 与 Perforce 数字签名
pnpm fixture:setup:win

# 启动并 Seed；服务只监听 127.0.0.1:16661
pnpm fixture:start:win

# 如需在当前终端手工执行隔离的 p4 命令
. .\.local\p4d-fixture\env.ps1
& $env:P4_PATH info

pnpm fixture:status:win
pnpm fixture:stop:win

# 确认不再需要后，停止服务并删除整个隔离目录
pnpm fixture:destroy:win
```

Windows Fixture 的二进制、Server Root、Workspace、日志、Ticket、Trust 和 P4ENVIRO 全部位于 `.local/p4d-fixture`。脚本会写入固定 Server ID，并在停止或复用端口前校验身份；如果 `16661` 被其他进程占用，脚本会拒绝继续，不会尝试停止该进程。

### macOS / Linux

```bash
# 如果系统已有 p4d，会直接复用，不重新安装
pnpm fixture:start
source .local/p4d-fixture/env.sh

# 完成测试后停止；数据保留便于排查
pnpm fixture:stop

# 确认不再需要后销毁全部 Fixture 数据
pnpm fixture:destroy
```

如果只有 `p4` 没有 `p4d`，脚本默认停止，不会擅自下载。可传入已有二进制：

```bash
P4D_PATH=/绝对路径/p4d pnpm fixture:start
```

确需下载时，必须同时显式提供官方 HTTPS 地址和 SHA-256；下载内容通过校验后才会启用：

```bash
P4D_ALLOW_DOWNLOAD=1 \
P4D_DOWNLOAD_URL='官方 p4d 下载地址' \
P4D_DOWNLOAD_SHA256='官方 SHA-256' \
pnpm fixture:start
```

Fixture 固定使用专用端口 `16661`，Seed 一个隔离 Workspace、一个已提交 CL 和一个 Shelf。脚本不会读取 `P4PORT/P4USER/P4CLIENT` 指向的真实服务器，也不复用用户 Ticket。自动化测试同样禁止连接真实服务器。

## 工程与安全约定

- 所有文本文件使用 UTF-8 和 LF。
- 禁止提交 `.env`、ticket、trust、密码和签名凭据。
- 禁止提交内网地址和未脱敏 Depot 数据。
- 本地 P4 环境优先通过 `P4CONFIG` 管理。
- 开发命令从仓库根目录执行。
- 不在初始化脚本中执行 sudo、强制卸载或覆盖不兼容工具。
- 合并前至少运行 `pnpm ci:quick`（默认并行且一次跑完，失败摘要与完整日志见 `artifacts/ci/logs/`）；涉及构建、打包或性能改动时再运行 `pnpm ci:local` 及对应的 `pnpm build`、`pnpm test`、`pnpm check`，只动打包/前端 mock 相关时先用 `pnpm ci:bundle` 快速自检。

### 凭据边界回归

- 不要用真实密码或 Ticket 测试日志；Rust/前端测试使用每次明确声明的唯一 sentinel。
- `cargo test --manifest-path src-tauri/Cargo.toml credential_sentinel_never` 验证 sentinel 不进入 OperationEvent、OperationResult、LogStore 内存/SQLite、Journal、诊断 JSON；`blocked_commands_fail_before_executable_resolution_or_process_start` 验证受控命令在解析 executable 之前被拒绝。
- `pnpm test:web -- src/features/tools/terminalSecurity.test.ts src/features/tools/terminalPreferences.test.ts src/features/tools/components/ToolsDiagnostics.test.tsx` 验证命令变体、历史清洗、Terminal 不回显以及 Settings 恢复入口。
- `pnpm test:e2e:p4d:win` 继续证明正常 `info/files/changes` 与窄 Trust/Login/Logout API 没有退化。该 Fixture 只使用 `.local/p4d-fixture` 的隔离凭据；不得把工作环境的 `P4PASSWD`、Ticket 文件或 Server 带入测试。
