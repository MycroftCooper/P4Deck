## 安全边界

- Terminal 不是系统 Shell，只解析 `p4` 子命令与参数。
- `-p/-u/-c` 由当前 Workspace Context 注入，Terminal 不能传入全局连接参数。
- 禁止 `-P` 和 `P4PASSWD=`；登录、改密和敏感命令不进入历史。
- `login/logout/trust` 不能通过通用 Runner 或通用 IPC stdin 调用，只能进入受控连接服务；密码仅作为单次 `login` stdin 写入子进程，不进入 Context JSON、OperationEvent、SQLite、命令历史或返回错误。Ticket 文件只传路径，不读取或返回内容。
- 连接服务把 SSL 未信任、未登录、Ticket 过期、网络、权限、配置、外部 SSO/MFA 等结果映射为稳定 camelCase 状态和恢复动作，前端不需要解析 P4 stderr；Trust 只接受当前请求绑定的 Server Context 和经校验 fingerprint，不开放任意 trust flag。
- 进程使用 `Command` 参数数组，不进行 Shell 字符串拼接。
- Fixture 使用固定 localhost 端口；E2E 显式注入 executable/server/user/client/ticket/trust，隔离 P4CONFIG/P4ENVIRO/P4PASSWD，不读取或回退到用户真实 P4 环境。
- 系统本地路径操作不接受可执行文件或额外参数：拒绝 depot path、相对路径、控制字符、不存在路径、Workspace 越界和符号链接越界；macOS 使用固定 `/usr/bin/open`/系统应用选择器，Windows 使用 Explorer/`SHOpenWithDialog`，全程不经过 Shell。

## 性能约束

- CL 与 Log 均采用窗口化 DOM；不存在全量 DOM 回退实现。
- CL 查询携带 `requestGeneration`，新查询结果只能由最新代际写入界面。
- 关键词输入 250 ms 防抖；Rust 将 P4 支持的范围、状态、用户、Client 和时间条件优先下推。
- 单次 UI 查询设置 20,000 条保护上限；后续继续扩展游标批次和增量详情缓存。
- 同 Server 总 P4 进程数限制为 4，修改命令限制为 1；大文件列表通过 stdin 分批输入，不创建逐文件进程。
- Action 通过 operation ID 推送 0–100 进度并支持排队中或执行中取消；输出超过 64 MiB 自动终止。
- 系统定位/打开通过 Tauri 异步 command 的 blocking worker 执行，系统选择器或 Explorer 不会阻塞 WebView UI 线程。
- Workspace `fstat` 状态通过独立缓存聚合 controlled/opened/out-of-date/conflicted 信号；缓存诊断只包含 hit/miss/coalesced/evicted/invalidated、耗时和失效原因，不暴露 cache key、路径或凭据。文件 Action、CL Action、Submit、手动刷新和 Connection 切换均使用连接/Workspace/路径/查询类型范围失效。
- Operation Journal 不保存命令参数、stdin、密码、Ticket 内容或文件路径，只保存不可重放的动作类别、结构化结果和脱敏日志引用；异常退出后的 queued/running 记录只标记 interrupted，不自动重放。
- LogStore 保持 10,000 条硬上限，用户策略限制为 1–30 天、5–50 MiB；Warning/Error 只发送带 operation ID 的 `diagnostic-alert`，是否展开由前端偏好决定，不抢焦点。
- 诊断导出固定写入应用数据目录下的 `diagnostics`，使用随机文件名、临时文件完成后原子改名，失败清理临时文件；当前最小格式为 `p4deck-diagnostic-json-v1` 单 JSON 文件，128 KiB 硬上限，包含 manifest、脱敏日志与结构化操作摘要，不包含 Workspace 文件、stdin、密码、Ticket 内容或原始命令参数。压缩包格式留待确有跨工具消费需求时再评估，不调用 Shell 压缩。

## 尚需继续深化的范围

本次完成可运行核心骨架和首条业务纵向切片。以下功能已有契约或入口，但要达到正式发行质量仍需迭代：

- 合并可靠分类目前是保守的多信号初筛；仍需懒加载 `describe`、integration/filelog 元数据并缓存。
- Submit 目前只提供校验入口，不会直接静默提交；完整 unresolved、out-of-date、锁、权限和确认流程待实现。
- CL 文件详情、多选拖放、部分 Shelf 的完整交互界面待实现；Rust 受控命令已支持路径参数。
- 设置页需要补充手动 Context、日志保留策略与 Warning/Error 自动展开开关。
- Windows localhost BE-002 已验证真实 `p4 info`、隔离 Ticket、Workspace/Depot 与 Sync/Edit/Add/Delete/Revert；SSL Trust、Broker/Proxy、SSO/MFA、Submit、Shelf/Unshelve 仍未验证。
- macOS E2E 与 macOS/Windows CI 平台冒烟仍需在对应设备执行。
