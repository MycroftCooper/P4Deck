# 命令速查

> 找命令只看这一页。所有命令都可直接 `node scripts/...`；`pnpm` 在本机要用 `pnpm.cmd`。

## 两条通道（先选通道，再找命令）

| 场景 | 通道 | 命令（就这些，别多跑） |
|---|---|---|
| **用户人验反馈 / 小 bug / 文案布局（默认）** | **敏捷** | `pnpm wf:agile --files <改动> --role <FE\|BE\|LEAD> --title "<一句话>"`：自动跑 `ci-fast` + 写证据 + 生成 5 分钟验收清单 → 用户按 `ACCEPTANCE.md` 验收；**不建候选、不 freeze、不跑全量 QA、不 apply** |
| 新版本发布/交付 | 发布 | 下方完整 9 步：候选 → `batch.mjs manifest` → `qa-approval` → `batch.mjs verify` → `batch.mjs apply --apply --confirm-dev-closed` → `ci:quick`/`ci:local` → 打包/版本校验 |

> 硬规则：**只有发版才跑全量 CI/全量测试/独立 QA/联合**；验收反馈一律敏捷，目标 5–15 分钟闭环。

## 敏捷通道

| 命令 | 作用 |
|---|---|
| `agile.mjs --files a,b --role <ROLE> --title "<一句话>"` | 跑 `ci-fast`、写 `artifacts/evidence/agile-<n>/`（REPORT/ACCEPTANCE/hashes/gate.log/backup） |
| `agile.mjs ... --plan` | 只打印计划，不跑门禁、不写文件 |
| `agile.mjs ... --skip-gate` | 只记录证据（仅文档或已验改动） |
| `agile.mjs ... --todo` | 顺带加一条人类待办（验收项） |
| `agile.mjs --since-baseline --role <ROLE> --title "..."` | 从 `baseline.mjs changed` 取改动 |
| `agile.mjs --help` | 参数与退出码 |

模板：`scripts/workflow/templates/agile-report.md`、`agile-acceptance.md`（改这两个文件即可调整回执/验收清单结构）。

## 状态与任务

| 命令 | 作用 | 实测 |
|---|---|---|
| `state.mjs check [--strict] [--verbose]` | 校验状态库（包/切片/依赖/负责人/证据） | 0.12s；默认只列 5 条告警 |
| `state.mjs queue --for <ROLE> [--ready\|--waiting] [--json]` | 我的队列；标出依赖链就绪/等待 | |
| `state.mjs next --for <ROLE> [--json]` | 下一个就绪任务（按优先级） | |
| `state.mjs board` | 生成 Markdown 看板（含「就绪」列与人类待办阻塞任务） | 0.13s |
| `state.mjs board --compact` | 极简：id/状态/优先级/负责人（给 agent） | ≈2k 字符 |
| `state.mjs task <ID> --for FE [--message\|--json]` | 单个任务单（依赖行标就绪/等待） |  |
| `state.mjs import` | 从 TODO 表迁移（保留 verification/归档状态） |  |
| `state.mjs accept <ID> --note "依据" [--evidence <路径>] [--force]` | 登记人工验收（置 `humanAccepted`、stage→done；缺 QA/Apply 事实才用 `--force` 补登历史验收） |  |
| `pnpm wf:release --version x.y.z [--note] [--apply]` | 发布：dev→master `--no-ff` merge + `v*` tag；默认 dry-run，校验门禁/工作树/版本 |  |
| `state.mjs archive <ID> --note "理由" [--evidence <sha>]` | 归档（前置 humanAccepted） |

> **依赖链**：`deps` 可填任务 ID 或人类待办 ID（`T01`…），来源是 TODO 表「依赖」列；就绪 = 全部依赖完成。`queue` 默认列出全部并标 `READY`/`WAIT`，`--ready` 只看可开工项，`next` 取第一个就绪。人类待办勾选后自动解锁下游并刷新看板。
>
> **父子任务**：TODO「关联子项」表 = 父子关系；父任务在子任务全部完成前不能 `accept`/`archive`，子任务可单独 `accept`；全部完成时父任务自动汇总完成（看板显示 `子任务 n/m`，已验收父任务不降级）。
>
> **看板折叠**：`看板.html` 与 DSH 看板里，Agent / 里程碑 / 人类待办 / 任务看板 / 归档以及各状态列都可点击标题折叠，展开状态记在 localStorage。  |
| `state.mjs restore <ID>` | 撤销归档 |  |

## 证据与门禁

| 命令 | 作用 |
|---|---|

## 更新日志与发布说明

## 批次与缓存

| 命令 | 作用 |
|---|---|
| `batch.mjs manifest --candidate <dir> --paths a,b --packages <ID>` | 冻结 manifest（同时落耐久证据目录） |
| `batch.mjs verify --manifest <f> --qa <f>` | 原树漂移/候选改动/QA 绑定 |
| `batch.mjs apply --manifest <f> [--apply --confirm-dev-closed]` | 默认 dry-run |
| `batch.selftest.mjs` | 批次工具自测（16 项，临时目录） |
| `baseline.mjs start` / `changed` | 不依赖 commit 的"本片改动"基线 |
| `cache.mjs status` / `clean --cargo` | 共享 Rust 缓存 1.3GB，可查可清 |
| `measure.mjs record/summary` | 量测；`sync` 会自动记一行 |
| `sync.mjs` | import → evidence → board → html 一条命令收尾 |
| `archive.mjs [--keep 2] [--apply]` | 交接文档轮转（默认 dry-run + 并发保护） |

## 性能实测（本机，2026-10-30 复核）

| 项 | 数值 |
|---|---|
| 共享 Rust 缓存 | 冷 67.1s → 热 5.6s（12×）；当前占用 **5.2GB**（`wf:cache status` 2.2s 可查） |
| `tsc -b`（typecheck） | **冷 10.3s / 热 1.5–1.7s**（此前无改动也要 12.5s：`noEmit` 项目缺 `composite`，每次都全量重查；已修） |
| 脚本自身 | check 0.13s / board 0.10s / queue 0.09s / sync 1.1s / 预检 0.41s |
| `baseline start/changed` | 0.5–3s（968 文件；不再扫 `src-tauri/target` 46GB） |
| `evidence --collect-temp` | **1.3s**（只扫候选根/evidence，跳过 target；原 123s） |
| 改一行 → `wf:fast --files <1 文件>` | **8.0s**（tsc 1.7s + prettier + vitest related；原 17.7s） |
| 全流程（改一行 + manifest→QA→verify→apply→evidence→board） | **≈11s**（B 段常数 2.6s；原 28s） |
| `ci:quick` 全量 | 门禁大头是 rust-test（30–35s）与 web-test（35–39s）；整体 ~53–82s |
| `wf:selftest:all` | ~7s（baseline 修复后） |

> 迭代用 `wf:fast --since-baseline`（开片先 `wf:baseline start`），freeze 前才跑 `ci:quick`。
> 磁盘提醒：`src-tauri/target` 曾涨到 66GB（2026-11-03 已清）、TEMP 共享 cargo 5.2GB、TEMP 候选 129 个 / 153GB——I/O 压力会让所有命令变慢，必要时 `cache.mjs clean --cargo` 并清理旧候选。

## 磁盘与缓存（2026-11-03 清理后：项目 6.55GB，其中 `target` 4.9GB）

| 位置 | 当前 | 说明 |
|---|---:|---|
| `src-tauri/target` | 65.9GB → 4.9GB | 清理前积累：63 套 metadata hash、94 个 incremental 会话（31GB）、4005 个 `.o`（8.9GB）、4 个残留 `.tmp*temp-archive`（2.2GB）；余下 4.9GB 是一次校验构建（`crate-type` 改 rlib 后单次 debug 构建，比之前少约 2GB） |
| `src-tauri/target-qa` | 0（已删，下次 QA 启动重建 ~5GB） | QA 独立 target，保证与普通 dev **可同时运行** |
| `.git/lfs` | 0.94GB | 本次 diff/收尾触发过 LFS 拉取；`cache.mjs clean --lfs` 只删未引用对象，可安全回收 |
| TEMP `P4Deck-*` 候选 | 106 个 | 旧候选已归档文字证据并清理（回收 41.7GB） |
| TEMP `p4deck-shared/cargo-target` | 5.2GB | 跨候选共享 Rust 缓存 |

```powershell
pnpm wf:close                                          # 批次收尾：sync + 磁盘体检 + 自动清增量缓存（≥2GB 时；--dry 预览 / --no-clean 跳过）
node scripts/workflow/cache.mjs status                 # 2.2s，列出各区体积
node scripts/workflow/cache.mjs clean --incremental    # 清增量缓存（29GB→0；下次编译变慢）
node scripts/workflow/cache.mjs clean --release        # 清打包产物
node scripts/workflow/cache.mjs clean --lfs            # 只删未引用 LFS 对象（安全）
node scripts/workflow/cache.mjs clean --temp-candidates --days 2   # 清 2 天前候选（先 evidence --collect-temp）
```

**流程层面的修正**（四件事）：
1. **构建产物有生命周期**：每批收尾跑 `pnpm wf:close`——`incremental` 超过 2GB 自动清（`--dry` 预览、`--no-clean` 跳过，阈值可用 `P4DECK_CLOSE_CLEAN_MB` 调）；`release` / `workspaceTarget` 等 >10GB 的项仍按提示显式清。
2. **QA 保持独立 target**：`dev:desktop:qa` 用 `src-tauri/target-qa`，可与普通 dev 同时运行、互不阻塞；代价是多占约 5GB，收尾按需 `cache.mjs clean --target-qa`。
3. **候选可回收**：候选必须用 `cargo-candidate.cmd`（共享 target），创建时加 `env-candidate.mjs --copy-tsbuildinfo` 复制 tsc 增量；收尾时 `evidence --collect-temp` 再 `cache.mjs clean --temp-candidates`。旧 `target-qa` 仅作兼容，`cache.mjs clean --target-qa` 可清。
4. **桌面端 `crate-type` 只留 `rlib`**：Windows/macOS 都不需要 `staticlib`（iOS）/ `cdylib`（Android），去掉后单次 debug 构建少产出 ~1.4GB `.lib` 和几千个 `.o` 中间文件；将来接移动端再在 `src-tauri/Cargo.toml` 加回。
