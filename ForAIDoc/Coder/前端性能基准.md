# 前端大列表性能基准

日期：2026-10-09。

## 命令与门禁

```powershell
pnpm test:perf
```

该命令使用固定 seed、7 轮 warmup 和 25 轮测量，直接调用生产代码路径，并生成：

- `artifacts/performance/frontend-latest.json`：环境元数据、p50/p95、总耗时、采样前后 heap/RSS 增量、阈值与 pass/fail；
- `artifacts/performance/frontend-latest.md`：同一次运行的简洁可读摘要。

产物目录被 Git 忽略，避免把不同机器的易波动结果混入源码；每次验收必须重新执行命令并留存所需产物。性能套件不进入默认 `pnpm test:web`，但虚拟 DOM 上界、键盘焦点、选择与 ARIA 等确定性结构测试进入常规 Web 测试。

数值门禁只使用项目既有目标：50,000 条搜索/筛选 p95 必须小于 50 ms。100,000 条筛选目前只记录信息，不虚构项目未定义的数值阈值；100,000 条虚拟列表以窗口 DOM 数量做确定性结构断言。

## 2026-10-09 本机结果

环境：Windows `10.0.26100` x64、Node `v24.16.0`、Vitest `3.2.7`、13th Gen Intel Core i7-13700K、24 logical CPUs。数据包含长路径、Unicode、不同文件状态/action、长描述和 Jobs 分布。

| 生产路径 | 数据规模 | p50 | p95 | 门禁 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| Workspace 状态筛选 | 50,000 | 0.539 ms | 0.651 ms | < 50 ms | PASS |
| Resource Unicode 名称搜索 | 50,000 | 1.337 ms | 1.421 ms | < 50 ms | PASS |
| Global Search 合并/去重 | 50,000 + 50,000 | 6.967 ms | 10.511 ms | < 50 ms | PASS |
| Workspace 状态筛选 | 100,000 | 0.627 ms | 0.648 ms | 信息项 | PASS |
| Pending CL 合并/排序 | 50,000 | 4.920 ms | 5.808 ms | 信息项 | PASS |

`PendingFileList` 的 100,000 条结构断言只挂载 24 行（门禁 `< 40`），总虚拟高度为 3,600,000 px。Pending 打开/搁置文件、Submitted 详情、Global Search、P4 Log、Operation Journal、Workspace/Depot 与既有确认目标列表均使用 TanStack Virtual 或既有窗口化路径，不再用全量 DOM 承载累积大列表。

JSON 中的 heap/RSS 是每个 case 多轮运行前后的采样增量，受 GC 影响，不能冒充进程峰值；这里只用于发现明显的无界增长回归。

## 验收边界

以上是单台开发机的合成数据自动基准，不是 Windows/macOS 固定设备认证。当前自动化环境无法枚举 P4Deck 原生窗口，因此尚未验证原生持续滚动 FPS、真实 Tauri 内存峰值、长时间滚动、真实屏幕阅读器或双平台焦点树。浏览器/jsdom 的结构断言不得表述为这些项目已通过。
