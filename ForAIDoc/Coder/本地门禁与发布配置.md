# P4Deck 本地门禁与发布配置骨架

> 当前事实：项目只有本地 Git，没有远端仓库，也从未运行远端 CI。CI 是代码质量检查工具，不是 Perforce 功能；它不会连接用户的 P4 Server。

## 日常本地验证

开发完成后先运行：

```powershell
pnpm ci:quick
```

该命令按固定顺序检查 CI 配置、机器摘要协议、发布配置测试、Prettier、rustfmt、TypeScript、Cargo check、Clippy，以及前后端单元测试。任一步失败都会非零退出，并在 `artifacts/ci/quick-latest.json` 写入机器可读摘要；摘要不收集环境变量或凭据。

发布候选前可运行：

```powershell
pnpm ci:local
```

它在 quick 基础上串行执行生产 Web 构建、前端性能门禁和后端 release 性能门禁，避免多个重任务同时争用机器或改写同一份性能报告。Windows 隔离 `p4d` E2E 默认不执行；明确需要时使用：

```powershell
$env:P4DECK_CI_RUN_P4D = "1"
pnpm ci:local
Remove-Item Env:P4DECK_CI_RUN_P4D
```

这只允许 Windows 的项目隔离 fixture，不能连接真实 Server。显式设置 `P4DECK_CI_RUN_P4D=1` 后，P4D 门禁属于“必跑”：缺少固定版本的 `p4`/`p4d`、fixture 脚本、Cargo 或项目清单都会非零失败，不会显示成通过。项目不会在门禁里自动下载二进制；本地可先人工运行 `pnpm fixture:setup:win` 准备经过哈希和签名验证的工具。

P4D 脚本和本地门禁使用稳定的 JSON 结果协议，不解析人类日志。摘要中的状态含义如下：

| 状态      | 含义                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------ |
| `passed`  | 步骤确实执行完成且退出成功；P4D 还必须返回合法的成功协议结果。                                               |
| `failed`  | 步骤非零退出、结果协议缺失/非法，或执行/清理失败；总体门禁失败。                                             |
| `skipped` | 仅表示可选的 P4D 检查因 fixture 前置条件缺失而未执行，绝不等于通过；若调用方已显式要求 P4D，总体门禁仍失败。 |

直接运行 `pnpm test:e2e:p4d:win` 而未要求必跑时，缺 fixture 会以 `skipped` 收口并保持零退出，方便日常开发；`ci:local` 显式选择 P4D 或远端样板勾选 `run_p4d` 时会自动切换为严格模式。

## 可选远端 CI 骨架

`.github/workflows/verify.yml` 只是未来建立远端仓库后可人工触发的验证样板。当前没有远端，因此它现在不会运行。即使以后启用，也只有 `workflow_dispatch`，不会因 push 自动触发，不读取 secret、不制作或上传安装包、不签名、不发布、不触发更新器。

样板使用最小只读权限、固定 Action commit、并发取消和任务超时。Windows/macOS/Linux 跑通用质量门；性能任务单独串行；localhost `p4d` 仅在人工勾选时于 Windows 运行。勾选后会设置严格模式，runner 上没有预先准备好的 fixture 就明确失败；样板不会为此自动下载程序，也不会把跳过伪装成成功。`pnpm validate:ci` 会离线拒绝未固定 Action、secret 引用、写权限、`pull_request_target`、缺少超时/并发或明显危险的 shell 管道。

## 签名与更新器骨架

日常开发使用 `src-tauri/tauri.conf.json`，其中 `createUpdaterArtifacts` 明确为 `false`，应用没有接入 updater runtime，也不会自动访问更新服务。

未来准备正式发布时，发布环境必须通过环境变量提供：

| 变量                                 | 要求                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| `P4DECK_RELEASE_MODE`                | 必须为 `1`                                                                           |
| `P4DECK_UPDATER_ENDPOINT`            | HTTPS；不得含凭据或 fragment；必须含 `{{target}}`、`{{arch}}`、`{{current_version}}` |
| `TAURI_UPDATER_PUBLIC_KEY`           | 非占位的 Tauri updater 公钥                                                          |
| `TAURI_SIGNING_PRIVATE_KEY`          | 只存在于发布进程环境；不得写入文件或日志                                             |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 只存在于发布进程环境；不得写入文件或日志                                             |
| `P4DECK_RELEASE_CHANNEL`             | `stable`、`beta`、`alpha` 或 `nightly`                                               |
| `P4DECK_RELEASE_VERSION`             | 明确的 SemVer                                                                        |
| `P4DECK_RELEASE_PLATFORM`            | `windows`、`darwin` 或 `linux`                                                       |
| `P4DECK_RELEASE_ARCH`                | `x86_64` 或 `aarch64`                                                                |

先运行 `pnpm validate:release`。只有全部输入合法时，`pnpm release:prepare` 才生成被 Git 忽略的 `src-tauri/tauri.release.generated.conf.json`。该 overlay 仅包含公开 endpoint、公钥、版本和 updater artifact 开关；私钥与密码不会写入。生成文件不能单独证明可发布，也不会自动调用 `tauri build`。

配置验证默认 fail closed：缺失值、占位值、HTTP endpoint、URL 凭据、非法公钥、channel/version/platform/arch 都会拒绝，诊断会脱敏。测试命令为 `pnpm test:release-config`。

## 尚未完成的外部发布验收

以下事项仍然未完成，不能因为本骨架存在就标记为通过：

- 创建远端并在 Windows/macOS/Linux 真实 runner 执行 CI。
- 安全注入真实签名凭据，并验证凭据轮换、吊销与审计。
- Windows 代码签名；macOS Developer ID、Hardened Runtime 与 notarization。
- 安装包安装/卸载、自动升级、失败回滚、离线与代理环境验证。
- updater runtime 接线、真实 HTTPS 服务、manifest/signature/channel 行为与旧版本升级矩阵。

在这些外部证据齐全前，P4Deck 仍不可作为公开或跨平台产品发布；它们不阻塞“当前 Windows 机器本人私用”阶段，该阶段以 [Windows 本机私用 TODO](../PM/Windows本机私用TODO.md) 为准。
