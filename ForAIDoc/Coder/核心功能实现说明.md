## 安全边界

- Terminal 不是系统 Shell，只解析 `p4` 子命令与参数。
- `-p/-u/-c` 由当前 Workspace Context 注入，Terminal 不能传入全局连接参数。
- 禁止 `-P` 和 `P4PASSWD=`；登录、改密和敏感命令不进入历史。
- `login/logout/trust` 不能通过通用 Runner 或通用 IPC stdin 调用，只能进入受控连接服务；密码仅作为单次 `login` stdin 写入子进程，不进入 Context JSON、OperationEvent、SQLite、命令历史或返回错误。Ticket 文件只传路径，不读取或返回内容。
- 连接服务把 SSL 未信任、未登录、Ticket 过期、网络、权限、配置、外部 SSO/MFA 等结果映射为稳定 camelCase 状态和恢复动作，前端不需要解析 P4 stderr；Trust 只接受当前请求绑定的 Server Context 和经校验 fingerprint，不开放任意 trust flag。
- 前端只依据结构化 `state/recovery` 呈现恢复动作；连接验证固定走 CLI 发现、服务器连接、登录状态三段。Context 有未保存修改时禁止验证/Trust/Login；保存只产生 `notTested`。Trust 需要当前 server、当前 fingerprint 和显式勾选三者一致，切换连接即清除确认。
- 密码输入使用非持久化 React state，提交时先复制到单次请求再立即清空 UI state；不写入 Storage、Context、URL、通知、错误或历史。外部 SSO/MFA 不显示普通密码表单，只允许用户完成外部流程后重新查询状态。所有连接动作使用请求代次与同步 busy guard，旧连接响应和重复点击不会更新 UI。
- Runtime 的 connection generation 在 Context 保存及连接/认证状态变化时递增；依赖 P4 Context 的 Workspace、Streams、Pending、Submitted、Files/Depot 等页面以该代次重建，避免同文本 Context 的重新登录继续展示旧连接响应。
- profile 文档是唯一持久化事实源：`schemaVersion=2`、revision、activeProfileId 与 profile 集合；profile 只包含 UUID v4、名称和 allowlist `P4Context`。旧裸 Context 在写入新 schema 前生成不含未知敏感字段的 allowlist `.legacy.bak`；损坏/未知版本/原子替换失败不覆盖原文件或内存状态。
- 活动 profile/Workspace 切换固定为“候选 Context → `p4 info` → `p4 login -s` → expected revision/generation 原子提交”。提交后取消全部 Runner operation，清除 Submitted/Search/status cache 与 Submit/Workflow token；失败不改变旧活动连接。Workspace 切换同时提交 Client 和服务器返回的 Root。
- Submit 只能经 `preflightSubmit` → `confirmSubmit` 状态机执行。泛化 FileAction 和 GUI 来源的通用 `run_p4` 均拒绝 submit；确认 token 一次性使用并绑定 Server/User/Client/Workspace、Context generation、CL 内容和文件状态，确认阶段在同 Server mutation lane 内复核后只执行 `p4 submit -c <编号 CL>`。
- Shelf/Unshelve/Resolve 只能经对应 `preflight*` → `confirm*` API 执行。它们与 Submit 共用一次性 token store，绑定 Connection/Workspace/generation/CL/显式文件集合/server digest 与本地内容；泛化 ClAction、FileAction 和 GUI `run_p4` 旁路均被关闭，Terminal 语义不变。
- Shelf/Unshelve/Resolve 对话框只接受与打开时目标快照一致、未过期且带 token 的 ready 预检。替换/删除 Shelf 需要危险确认；Unshelve 不提供 force 覆盖；Resolve 只显示后端允许的可执行策略。结构化 partial/rejected/failed/cancelled/unknown 或任一文件 blocked/unknown 均不显示成功，并按 refresh advice 局部合并 Pending、失效文件状态及关联 operation/log。
- Pending 写入只经 `mutatePendingChange` 执行。创建/编辑保留完整 Jobs；删除只允许编号 CL 并由后端复核 files/shelves/Jobs 真正为空；移动固定打开对话框时的 depot path 与候选快照，目标或连接变化使确认失效。成功使用 `affectedChanges` / `refreshedChanges` 局部合并，失败或刷新不确定时保守刷新相关状态且不显示全成功。
- SubmitDialog 将无 token 的 blocked 预检视为合法结果，分别显示 confirmed blocker、confirmed warning 与 unknown；只有 ready、目标一致、token 有效且用户确认整个 CL 时才调用 `confirmSubmit`。结构化 rejected/failed/cancelled/unknown 均保持失败语义，并按 refresh advice 更新 Pending、Submitted 与 Workspace。
- 进程使用 `Command` 参数数组，不进行 Shell 字符串拼接。
- Fixture 使用固定 localhost 端口；E2E 显式注入 executable/server/user/client/ticket/trust，隔离 P4CONFIG/P4ENVIRO/P4PASSWD，不读取或回退到用户真实 P4 环境。
- 系统本地路径操作不接受可执行文件或额外参数：拒绝 depot path、相对路径、控制字符、不存在路径、Workspace 越界和符号链接越界；macOS 使用固定 `/usr/bin/open`/系统应用选择器，Windows 使用 Explorer/`SHOpenWithDialog`，全程不经过 Shell。

## 性能约束

- CL 采用窗口化 DOM；P4 Log 每次最多渲染 100 条游标页并按需追加，不再一次拉取/渲染 10,000 条。
- CL 查询携带 `requestGeneration`，新查询结果只能由最新代际写入界面。
- 关键词输入 250 ms 防抖；Rust 将 P4 支持的范围、状态、用户、Client 和时间条件优先下推。
- 单次 UI 查询设置 20,000 条保护上限；后续继续扩展游标批次和增量详情缓存。
- 同 Server 总 P4 进程数限制为 4，修改命令限制为 1；大文件列表通过 stdin 分批输入，不创建逐文件进程。
- Action 通过 operation ID 推送 0–100 进度并支持排队中或执行中取消；输出超过 64 MiB 自动终止。
- 系统定位/打开通过 Tauri 异步 command 的 blocking worker 执行，系统选择器或 Explorer 不会阻塞 WebView UI 线程。
- Workspace `fstat` 状态通过独立缓存聚合 controlled/opened/out-of-date/conflicted 信号；缓存诊断只包含 hit/miss/coalesced/evicted/invalidated、耗时和失效原因，不暴露 cache key、路径或凭据。文件 Action、CL Action、Submit、手动刷新和 Connection 切换均使用连接/Workspace/路径/查询类型范围失效。
- Operation Journal 不保存命令参数、stdin、密码、Ticket 内容或文件路径，只保存不可重放的动作类别、结构化结果和脱敏日志引用；异常退出后的 queued/running 记录只标记 interrupted，不自动重放。
- LogStore 保持 10,000 条硬上限，用户策略限制为 1–30 天、5–50 MiB；Warning/Error 只发送带 operation ID 的 `diagnostic-alert`，是否展开由前端偏好决定，不抢焦点。
- 诊断导出固定写入应用数据目录下的 `diagnostics`，使用随机文件名、临时文件完成后原子改名，失败清理临时文件；当前最小格式为 `p4deck-diagnostic-json-v1` 单 JSON 文件，128 KiB 硬上限，包含 manifest、脱敏日志与结构化操作摘要，不包含 Workspace 文件、stdin、密码、Ticket 内容或原始命令参数。压缩包格式留待确有跨工具消费需求时再评估，不调用 Shell 压缩。
- 后端性能入口 `pnpm test:perf:backend` 仅在显式 `backend-perf` feature 下编译独立 release binary，不混入普通 Rust 单测；确定性门禁覆盖 parser/domain 条目与分类、serde round-trip、TTL/LRU/并发合并/失效、cursor 错配拒绝和 Unicode 去重。项目尚未定义后端数值阈值，所有 p50/p95 均为信息项。
