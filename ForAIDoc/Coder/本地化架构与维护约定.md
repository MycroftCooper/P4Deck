# 本地化（i18n）架构与维护约定

本文是 P4Deck 前端文案与语言的唯一权威说明。改造背景与历史基线见
[本地化现状调研](../../artifacts/l10n/调研-本地化现状.md)（`artifacts/` 不入库）。

## 1. 一句话规则

**所有面向用户的文案只允许写在两个目录（catalog）里**，组件通过 `t()` / `tFor()`
取用；`src/` 其它任何位置出现中文字面量都会被 CI 拦截。

## 2. 目录结构

```text
src/shared/
  i18n/
    index.ts        对外出口：t / tFor / useT / useLocale / useIsZh / changeLocale
    t.ts            纯函数解析器（无 React 依赖），模块级 locale 单例
    types.ts        MsgParams / Catalog / 复数与占位符正则
    catalog.zh.ts   中文词条（唯一事实源，MsgKey 由它推导）
    catalog.en.ts   英文词条（Record<MsgKey, string>，漏 key 编译期报错）
    i18n.test.ts    解析器与词条对齐测试
  i18n.ts           兼容层：保留旧的 messages[locale] 扁平对象 + 运行时再导出
  locale.ts         isZh() / pick()，供需要按语言分支的代码使用
```

`src/shared/i18n.ts`（文件）与 `src/shared/i18n/`（目录）同时存在是刻意的：
TypeScript 优先解析同名文件，历史上已有大量 `import { t } from "…/shared/i18n"`，
兼容层负责把调用导到新实现。**新代码可以直接从 `shared/i18n` 引入**，两条路径等价。

## 3. 三种调用方式，按场景选择

| 场景 | 用法 | 说明 |
|---|---|---|
| 组件内 | `useT()` 拿到 `t` | 订阅 locale 变化，切换语言即时重渲染 |
| 顶层/工具函数 | 直接 `import { t }` | 读取当前模块级 locale |
| 组件带 `zh` 参数/prop | `tFor(zh ? "zh-CN" : "en-US", key)` | 语言由调用方决定，**不读全局** |

第三种是关键：像 `PassiveStatus`、`WindowControls`、`LogView`、`PreviewTable`
这类组件把 `zh` 作为公开契约的一部分，测试会用 `zh={false}` 渲染 English。
它们必须用 `tFor`，否则全局 locale 会覆盖调用方意图。

### 禁止事项

```ts
// ❌ 用译文本身判断语言——改一个词条就会让整个 UI 翻掉
const zh = t.files === "文件";
const zh = t.language === "Switch to English";

// ✅
import { isZh } from "../shared/locale";
const zh = isZh();
```

这条曾是本项目最大的隐患：改造前有 51 处这样写（`PendingPage` 里就有 49 处）。

## 4. 词条写法

键按**业务域**分组，不按页面：`common.` / `navigation.` / `changes.` / `files.` /
`settings.` / `contextMenu.` / `browse.` / `tools.` …

```ts
// 插值
"changes.count": "{count} 条",            // 中文
"changes.count": "{count, one: # change, other: # changes}",  // 英文复数

// 调用
t("changes.count", { count: 3 });   // zh: "3 条"  en: "3 changes"
```

- 占位符用 `{name}`；复数用内联 `{count, one: … , other: …}`，`#` 代表数字。
- 复数分支由 `Intl.PluralRules` 按语言选择，中文只有一个分支。
- **不要拼接句子**。中英词序不同，`a + b` 无法翻译；把整句做成一条带参数的词条。

## 5. 缺失与回退

解析顺序：当前 locale → `zh-CN` → 词条键本身。

- 缺 key 时**永远不显示空白**，显示 key 本身，方便在评审和测试中发现。
- 开发环境（`import.meta.env.DEV`）下每个缺失 key 只 `console.warn` 一次。
- 因此 `catalog.en.ts` 的类型约束 + 解析器回退构成双保险。

## 6. 门禁

```bash
pnpm validate:i18n-literals   # 禁止 src/ 出现中文字面量
pnpm i18n:audit               # 审计「用译文参与逻辑判断」的地方
pnpm i18n:converge            # 存量三元表达式收敛（默认 dry-run）
```

`validate-no-cjk-literals.mjs` 允许的例外：

| 例外 | 原因 |
|---|---|
| `src/shared/i18n/catalog.zh.ts` / `catalog.en.ts` | 词条本体 |
| `src/app/context-menu/labels.ts` | 中文标签 → 词条 key 的**索引**，不是渲染文本 |
| `src/app/context-menu/catalog.ts` | 菜单清单，`label`/`title` 一律经 `menuLabel()` 渲染 |
| 注释、`// i18n-exempt` 标记 | 非 UI 文案 / 显式豁免（需写清理由） |
| `*.test.ts(x)` | 测试夹具 |

新增文件中确实存在非 UI 的中文（如 P4 路径常量）时，在该行加 `i18n-exempt` 注释。

## 8. 新增文案的标准流程

1. 在 `catalog.zh.ts` 对应业务域分组里加一条，键名表达语义（`settings.saveFailed`）。
2. 在 `catalog.en.ts` 同键补英文——漏写会**编译失败**（`Record<MsgKey, string>`）。
3. 组件内用 `useT()` 取 `t`，或按第 3 节选择 `t` / `tFor`。
4. 跑 `pnpm test:web`；`i18n.test.ts` 会检查两本词条键一致、占位符一致。

## 9. 从未迁移区域继续改造

批量收敛用 `scripts/i18n-converge.mjs`：

```bash
node scripts/i18n-converge.mjs            # dry-run，输出 artifacts/l10n/codemod-plan.json
node scripts/i18n-converge.mjs --write    # 落盘
node scripts/i18n-deshadow.mjs --write    # 处理 t 被局部变量遮蔽的文件
```

脚本约束（都是踩过的坑）：

- 只匹配**单行**三元表达式；跨行匹配会吞掉相邻 JSX。
- `??` 与 `||` 混用必须加括号。
- 生成的 key 若与已策划词条冲突，**拒绝覆盖**并改名。
- 收敛块写入时与已有块合并，不整体替换。

## 10. 后端与日期

- **Rust 侧保持英文**，不拼中文。前端 `shared/localizeError.ts` 与
  `shared/notice.ts` 按英文原文映射译文；长期应改为错误码，属独立任务。
- 日期/数字一律 `formatLocalTime(value, locale)`（`shared/lib/localTime.ts`），
  **不要用无参 `toLocaleString()`**——它跟系统区域走，不跟 UI 语言走。
