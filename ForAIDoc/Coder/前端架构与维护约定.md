# 前端架构与维护约定

本阶段整理保留现有页签、目标锁定、分屏、弹出、边栏和主题交互，不更换 UI 框架，也不扩大 P4 操作范围。原有持久化键及页签 ID 格式保持兼容。

服务器数据的缓存分类、读取流程、刷新触发与操作分类（后台异步 / 同步阻塞）统一见 [数据缓存与操作架构](数据缓存与操作架构.md)；新增页面或操作先走那里的检查清单。

依赖方向：工作台装配功能页面；页面使用 Backend 契约，不自行拼接 IPC 或执行进程。Dockview 的实例对象不进入业务页面。页签向页面传递目标字符串、锁定状态与目标修改回调。

`tsconfig.app.json` 一个项目同时覆盖 `src/` 与 `tests/`（根 `tsconfig.json` 的 references 另串 `tsconfig.node.json`），因此 `pnpm check:web` / `pnpm check` 的 `tsc -b` 会同时检查产品代码与 `tests/` 下的 Playwright spec、QA 夹具。新增测试文件不需要额外配置，但必须自己修好类型错误——`tests/` 不再是不受检查的区域。

### 目录归属规则

新增文件前先按下面五条判断放哪里，避免 `app/` 再次长成第二个 `features/`：

1. **有明确业务域**（CL、文件、Workspace、设置、搜索…）→ `features/<域>/`，不得放进 `app/`。
2. **跨多个域复用、且无业务归属**的 UI 基建 → `app/`；纯数据/工具且不依赖 React → `shared/lib/`。`shared/` 不得成为杂物目录。
3. **域内部结构**：域根放纯策略、纯数据与 hook，React 组件（含组件测试）放该域的 `components/`。`changelists`、`files`、`tools`、`browsers` 已按此组织；其余域当前文件数少、保持扁平，单个域根文件超过约 15 个时必须拆分，新增域从第一天起就用 `components/`。
4. **验收证据只允许出现在 `tests/qa/` 的 QA 写域三个子目录**，或仓库根 `artifacts/`（已被 `.gitignore` 忽略）。不得把截图、结果 JSON 写到 `src/` 其他任何位置。
5. **单文件目录不用于表达分层**：一个目录里只有一个文件时，说明该"层"尚未成立，应并回相邻目录，而不是保留空壳目录。当前只剩两处刻意的例外：`src-tauri/src/bin/`（Cargo 的 bin 约定）与根 `assets/`（纯素材位）。

## 状态归属

- App 负责装配；useWorkspaceSelection 统一持有选择集合、主目标和当前目录，并协调 useCommandTarget。不要再添加并行的 onSelect props 通道。
- selectionState.reconcileSelection 是纯函数：异步补全仅更新仍被选中的同一批路径，不能把新的选择或清空状态覆盖掉；无变化时保留状态引用。
- SelectionContext 是三个文件列表的唯一选择入口；Provider 值与命令转发回调保持稳定。
- usePreferences 管理主题、语言、密度、字号和跨窗口同步；设置页只编辑它，不反向成为 App 的状态仓库。
- useRuntime 处理连接初始化与更新；初始化返回晚于连接更新时不会覆盖新连接。
  当前或最后一个已保存连接均允许删除，前端统一使用模态确认框。删除当前连接必须原子清空 activeProfileId 与运行时 Context、递增 generation，并广播 connection-changed 清理旧请求和缓存；不得自动启用另一条连接。显式保存的空列表或无当前连接状态重启后不得回退环境变量。无连接时业务页显示空状态，设置和日志仍可访问。
- Dockview 是页签实例与活动组的事实来源。panels.ts 仅负责纯策略，不再保留另一套 afterClose 邻居选择算法。
- SubmittedPage 自己拥有筛选、稳定查询快照、opaque cursor 与累计 stats；连接/筛选变化和卸载都会取消旧 operation、清空旧页并使旧响应失效。分页错误保留已有结果与 cursor 供重试，详情选择只在仍存在的行上生效。保存过滤器经版本化白名单 schema 写入本地 Storage，不持久化连接 Context、cursor 或凭据。
- PendingPage 自己拥有版本化本地 filter/sort、request generation、operation cancel、cursor 链和累计实体集合。Default 只从 `defaultChange` 接收并排在首位；numbered 页按 change ID 去重。筛选、排序、连接或刷新变化必须取消旧 operation、清空旧 cursor 链；创建/编辑/删除/Submit/Shelf/Unshelve/Move 后只允许先按稳定 ID 合并反馈，再启动新的第一页，禁止继续消费写前 cursor。
  同一查询刷新时保留当前实体、展开状态和选择，成功后整体替换第一页及 cursor，失败保留旧结果；仅在筛选/排序/连接身份变化时先清空数据。Submitted、History、Diff、Revision Graph 等只读页面沿用相同的保留规则，不能用全屏加载态覆盖已有结果。
- Diff、History 与 Revision Graph 必须通过 `reviewRequests.ts` 建立 owner lease，禁止直接 `Promise.then(setState)`。identity 至少包含完整 Connection/Profile/generation/scope/tab 与本次 selector/node/cursor/expand target；只有 `isCurrent(lease)` 且当前 view owner 未变时才能写 data/error/loading/cache。cleanup、路径/页签/连接/selector/node/cursor 切换都要 abort lease 并调用后端根 operation 取消；取消错误不进入普通错误区。owner envelope 在 render 阶段屏蔽旧数据，不能依赖 effect 事后清空。
- Diff 默认左右对照：`FileReviewPage` 只负责请求 owner、缓存与刷新，`DiffView` 负责紧凑工具栏、分栏头版本选择及本地导航。区块导航、查找、行号跳转、选取文本和滚动不能触发后端请求。`diffRows.ts` 从 unified 结果线性生成对齐行；完整 Diff 同时返回已加载且受既有大小限制的 `leftText/rightText`，验证与 patch 一致后补齐未改动上下文，保留原有区块边界和源行号。部分、截断或旧缓存结果仅展示已有 patch，不把缺失内容当成未改动。`SplitDiff` 共享一份虚拟行窗口并同步纵向滚动，横向独立滚动；全选只包含当前侧实际已加载的文本。查找始终覆盖两侧，命中携带 side，按行顺序导航；相同上下文只计一次并同时高亮，两侧不同正文分别计数。字面匹配、不区分大小写，最多保留 10,000 个命中并显示超限标记。行号跳转单独选择目标侧，使用各侧源行号索引，不能把 padding 行算作文件行；切换跳转侧或点击分栏不得改变查找范围。Diff 默认折叠未改动上下文但保留每个 hunk 自带的 3 行上下文（相邻 hunk 间 >3 行的区间折叠成可点开的展开条；工具栏"展开全部"可显示整文件）；当后端未提供完整左右文本（partial/truncated）时，DiffView 默认显示完整原始补丁并提示上下文不可展开，保留"结构化视图"切换，避免出现只能看到折叠提示、无法查看内容的死胡同。
- Diff 路径仅保留在 Dock 顶部的 `DiffPathInput`。显示路径相对当前工作区根目录，panel target 保持完整文件标识；Depot 路径只通过共享 `resolved-address` 缓存中的真实映射缩短，禁止推测或截掉 Depot 前缀。路径编辑在本地处理，Enter 或完整路径粘贴才切换目标；`address.ts` 负责引号、分隔符、file URL、相对路径补全与格式化。映射读取不扫描目录，复用 shell 的同一缓存键，缓存/编辑状态按连接与目标隔离；无映射时保留原路径，不能捏造本地副本。
- 文本 Diff 的修订和 Shelf 正文通过结构化 `p4 print` 的 `data` 块原样拼接，不能从日志行重建。后端仅在比较时将 CRLF 统一为 LF，统计和 `identical` 必须遵循同一规则；不能 trim 正文或用 `lines().join()`，以免吞掉空白与末尾换行。末尾缺少换行仍是真实差异，前端在对应侧标注；预览、原始字节与 digest 保持各自原有语义。
- History/Graph 分页要分别记录 pending 与 consumed cursor；重复或不前进 cursor 终止继续加载但保留已可信结果，失败页保留当前集合。History 以 depot path + revision 去重；Graph 节点按 ID 去重并允许真实节点替换占位节点，边按完整语义 identity 去重。选择恢复只允许指向新集合中仍存在的实体。
- ToolArea 拥有日志及操作事件。事件频繁到达时不会逐条更新 App 的状态；通过窄的命令接口打开工具区或刷新日志。
- FilePreviewPage 负责呈现（表格渲染在 PreviewTable）；useFilePreview 负责异步数据、缓存 identity 与 sheet 维度。预览上限按格式分派：文本 2 MiB、图片 8 MiB/2000 万像素、表格有界页 500 行×64 列；触顶返回部分结果并显示截断原因。
- ResourceExplorer 固定显示工作区或 Depot 根树；useResourceTree 仅保存按连接隔离的展开路径，目录数据复用 workspaceCache。Workspace 展开先读本地目录、P4 状态在本地结果之后异步 enrich；Depot 展开先从 IndexedDB 恢复稳定 scope 的路径快照，再后台重验。已有数据时后台 `isFetching` 不显示占位行、不阻塞展开；只订阅可达的展开目录，收起父目录取消失去观察者的本地/状态查询；列表保持扁平虚拟化，箭头和左右键展开折叠，目录双击不再导航。筛选仅针对当前展开的目录，保留匹配项的祖先，不触发全盘递归查询。
- 当前连接验证以实际 P4 参数匹配，不以配置草稿是否 dirty 判断：名称、Swarm URL 和 Windows Root 的等价写法不应阻止验证结果同步。不同 Server/User/Workspace/凭证路径的草稿及迟到结果不得覆盖当前运行时；同一代次的迟到“尚未验证”通知不得抹除已发布的成功验证，单纯状态更新不重置资源树身份。

## 性能与可靠性

1. 业务页通过 React.lazy / Suspense 按需加载。默认文件列表保持直接加载，错误边界限定在单个页签内。
2. 文件侧栏与文件主列表使用同一个 QueryClient 和连接隔离的 query key；`workspaceQuery` 消费完整 `WorkspaceListing`，并发请求去重、短期缓存和刷新结果共享。每次请求生成 operation 前缀，AbortSignal 取消整组后端子命令；手动刷新显式传 `refresh=true`，不能只失效 React Query。Depot 未选中、资源侧栏折叠时不主动加载其查询；展开仍复用缓存，不清空筛选和选择。
3. 拖动分隔线引起的布局保存合并为 120ms 延迟写入；pagehide 时冲刷。页签类型集合不变时，不重复通知 App。
4. 保留虚拟列表和预览文件大小限制。P4 进度来自事件，100ms 合并渲染、不保存输出历史；磁盘容量仅在桌面版通过本地 IPC 每分钟刷新，后台窗口暂停定时刷新，不访问 P4。
5. Pending 顶层卡片和卡内文件使用两层独立 TanStack Virtual。顶层按 change ID 提供 `getItemKey`、动态 `measureElement` 与 overscan；展开状态、选择、焦点目标、拖放来源/目标均保存稳定 ID，不保存 virtual index。Default 折叠卡常驻 range 并 sticky；展开高行参与测量。原生拖放只接受当前挂载目标，滚动负责挂载后续目标；键盘/右键 Move 对话框可直接输入离屏 CL ID，并由后端预检确认。
6. subscribeSafely 处理“组件先卸载、监听注册后完成”的竞态，避免泄漏监听。
7. 偏好与布局存储失败不应令 UI 崩溃；损坏的页签目标、终端历史和高度进行校验。
8. 工具栏与右键菜单复用 commandPolicy 能力判断和 CommandExecutionContext 执行入口；selectionCommands 负责批量去重及目录递归文件规格。
9. 样式清理了 181 条被后续相同选择器覆盖的声明；保持必要的层叠顺序，避免为了分文件重排交互样式。主题变量独立维护。
9. 启用 TypeScript 未使用变量/参数检查，以及 Prettier 格式检查，防止重新堆积超长行和废弃代码。
10. 活动栏使用 panels.ts 派生的 activityPageIds，仅包含全局页面；设置独立固定在底部。旧下拉菜单逻辑及其样式已删除，不维护第二份入口可见性列表。
11. AppControls 只处理底部语言/主题控件，与 TopBar 分离；status.css 维护状态栏样式，避免继续往 commands.css 追加无关样式。顶部连接灯读取实际连接状态，演示模式在提示中明确标注。
    底部 P4 进度入口始终可展开，空闲时菜单仅显示“P4 空闲”；忙碌时按 operation ID 展示脱敏命令、排队/执行状态与进度。单项取消使用红色方块图标按钮并复用 cancelOperation；菜单底部提供取消全部，调用 Runner 的 cancel_all（包括已注册的操作组），等待结束事件后才移除任务。工具栏不再显示取消按钮；状态栏仅保留活动任务元数据，不保留 stdout 或事件历史。
12. 搜索文件与搜索 CL 切换时清除示例结果和结果选中项，分别保留输入草稿；CL 模式不能通过任意关键词提交。
13. Workspace 行只依据 `WorkspaceFileStatus` 展示可组合角标：opened/move、modified/missing、out-of-date/not-synced、unresolved、ignored provenance、symlink 与 partial/error/unknown。列表级 partial/error 必须保持可见，title/读屏文本包含全部 evidence；目录不得推断子项状态，也不得为每行额外请求。Files/Depot 继续窗口化，不把最多 10,000 项完整挂入 DOM。
14. 自动刷新间隔通过 `UiPreferences.autoRefreshMinutes` 保存为非负整数分钟，默认 5，0 关闭；设置修改即时生效，并通过现有 StorageEvent 同步到其他窗口。底部快捷暂停使用 `autoRefresh` 保留上次间隔以便恢复；设置中暂停时显示 0。计时器每分钟检查是否到期，隐藏或离线窗口暂停，焦点/重新可见/恢复联网也必须满足配置的间隔。切页签不重建协调器、不立即刷新；初次挂载由页面自身加载。进行中的读取合并重复自动触发，完成后重新计时，禁止全局 cancelQueries 打断页面。自动刷新事件每轮只广播一次，仅主动 refetch 活动的 Workspace/Depot 文件查询，禁止把磁盘容量、Pending 等其他查询一起重刷；用户操作后的定向更新仍即时执行。

这些是可验证的结构和请求次数改进，不代表已经测得真实 P4 环境的 CPU/内存降幅。大量文件、慢服务器及 Windows/macOS 原生多窗口仍需专项性能和实机验收。

## 操作弹窗的组织与维护

- `Dialog` 只管呈现与交互基础：来源 document、原生模态、初始焦点、键盘循环、关闭/回焦、滚动与忙碌。它不知道 P4 命令，也不读取业务目标。
- `useDialogRequest` 管理异步请求的生命周期；`useCommandDialogs` 用判别联合协调命令弹窗，保证同一 App 实例只能打开一个命令弹窗。CommandBar 只负责能力判断、构造目标快照、等待确认与调用已有执行契约，不再维护六套弹窗状态。
- 业务表单位于 `features/changelists/components` 和 `features/files/components`。`TargetList`、`PreflightStatus` 和危险范围确认复用基础组件；表单校验不冒充服务器预检。
- `FileClWorkflow` 是文件入口到 CL 操作的适配层：显式打开时读取 Pending，验证所有文件归属；跨 CL 先明确分组或跳过项，再复用同一 Move/Shelf 表单，不静默缩小操作范围。
- 工具栏、菜单和页面按钮应复用流程/菜单工厂。菜单将原始触发元素贯穿传递给弹窗，不能用主窗口的 activeElement 猜来源。跨 document 测试并不替代原生 Win/mac 验收。
- 异步数据必须按连接隔离；关闭、卸载和连接变更取消旧请求。真实操作结果由 `fileActionFeedback` 解释：非零退出码、取消与错误不能显示成功，异常可能已部分执行，不承诺回滚。
- 新增真实执行适配器时保留预检身份、有效期及完整范围验证。UI-only 流程继续明确显示“不执行”；不要为了让按钮能点就绕过缺失的预检。
- `?workflow-audit` 仅开发模式加载，提供无服务器调用的表单/虚拟列表合成场景。`testHarness` 是新对话框测试的公共基础；布局实测、行为单测与原生验收各自记录，不互相替代。

## 新增页签的流程

1. 在 app/panels.ts 增加元数据：中英文名称、global/file、local/depot 目标来源。
2. 在 features 对应领域实现组件；需要访问数据时使用 Backend 接口。
3. 在 PageRenderer 加入按需加载与 switch 分支。新增类型若遗漏分支，穷尽检查会报错。
   全局页面会自动进入 activityPageIds，需要同时补充 ActivityBar 的图标映射；类型检查会检查遗漏。
4. 文件页签使用传入的 target / locked / onTargetChange，不另建一套全局选中文件状态或自己写布局存储。
5. 若增加原生弹出页签类型，更新 Rust open_panel_window 的允许列表。该列表是跨进程安全边界，不与 UI 注册表强行共用运行时代码。
6. 将页面样式放在对应样式文件，通过 styles.css 有序引入；不要在文件末尾反复补同选择器覆盖。
7. 添加策略/数据测试，再验收关闭、多开、锁定、主题、布局恢复和错误状态。

## 本轮整理后的待验收边界

- 搜索已接生产全局查询：Submitted/Pending、Workspace/Depot 文件与 Job 五类结果均带稳定 identity、分页与导航 target；Mock 继续明确标记 simulated，不伪装服务端数据。

- 现有共享 workbench.css 仍较大。本轮只删除确认无引用的旧菜单/页签 CSS，不做未覆盖业务页面的大规模视觉改写。
