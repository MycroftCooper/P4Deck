# 右键菜单设计与校验清单

状态：设计基线与原始核查留档。日期：2026-09-29。当前实现及验收见 [实现与验收记录](../Coder/右键菜单实现与验收.md)。

逐对象、逐菜单项的实施对照表见 [右键菜单对象与菜单项总表](右键菜单对象与菜单项总表.md)。后续按该表逐项登记、实现和验收，本文保留交互规则与设计依据。

本文最初用于实现前方案校验；以下“首期/后续”是原业务能力规划，不等于后端功能已经完成。后续用户已要求实现全部菜单 UI：因此尚未接通的高级项现在集中展示于“更多操作（待接入）”并明确禁用，覆盖原稿中“不展示占位”的建议。统一 Diff 当前没有左右独立文本面板，对应菜单采用差异文本/两侧标识文案，不冒充单侧文件内容。其余对象、目标和安全约束继续有效。

## 1. 实现前核查（历史记录）

| 区域 | 当前事实 | 缺口 |
| --- | --- | --- |
| 文件页 Files | 有简易右键菜单：预览、同步、签出、添加、标记删除、还原、Diff、History、Revgraph 等；复用工具栏执行入口 | 缺少统一菜单壳、完整分组、复制/定位/系统打开；需要统一键盘和边界行为 |
| Depot / 工作区资源侧栏 | 右键更新选择集合 | 没有弹出菜单 |
| Pending 文件行 | 屏蔽默认右键事件 | 没有菜单；部分页面按钮仍是占位 |
| CL、Workspace、Streams、文件查看页 | 有部分页面按钮/后端接口 | 尚无统一右键体系，不能把接口存在等同于交互完成 |
| 页签 | 有关闭、锁定、分屏、弹出窗口等入口 | 未实现本方案的自定义统一右键菜单 |
| 搜索 | 文件 / CL 两种模式，当前是 UI 演示 | 示例结果不得触发真实 P4 操作 |

核查入口：`FileWorkbench.tsx`、`ResourceExplorer.tsx`、`PendingPage.tsx`、`commandPolicy.ts`、`CommandBar.tsx`、`panels.ts`、`docking/chrome.tsx`、`shared/contracts/types.ts`。

## 2. 总原则

1. 菜单按“对象”定义，而不是每个页面复制一套。文件出现在侧栏、Files、CL 或搜索结果时，复用动作定义，但保留来源和版本语义。
2. 右键是工具栏的补充入口，不是另一套执行逻辑。同一个命令的可用条件、确认、进度、错误必须一致。
3. 隐藏与对象根本无关的项；暂不满足条件的常用项保留置灰并说明原因；尚未实现的高级功能首期不展示，避免堆满无效入口。
4. 菜单立即打开，不等 P4 请求。不为每项菜单单独查询服务器；缺少能力数据时显示“检查中”，复用缓存异步补全。
5. 文件操作、CL 操作、版本操作分别建模。历史版本和 shelf 内容不假装成当前工作区文件。
6. 普通点击“预览/历史”等沿用现有未锁定页签复用规则；“在新页签中…”明确创建新实例，并建议默认锁定目标。全局页签不多开。
7. Windows/macOS 语义一致，系统定位文案可分别显示“在资源管理器中定位 / 在 Finder 中定位”。浏览器演示明确禁用系统动作。

## 3. 对象覆盖范围

| 对象 | 菜单定位 | 建议阶段 |
| --- | --- | --- |
| 工作区 / Depot / Files 的单文件、文件夹 | 主操作菜单 | 首期 |
| 多个文件、多个文件夹、混合选择 | 批量菜单 | 首期 |
| 资源树根、列表空白区 | 容器菜单，不冒用上次文件选择 | 首期 |
| Pending CL（含 Default）、CL 内工作文件 | CL 菜单 / 文件菜单 | 首期基础，完整 CL 流程后续 |
| Shelf 分组、搁置文件 | 搁置对象菜单 | 后续完整 CL 流程 |
| Submitted CL、其中文件 | 已提交记录 / 精确版本菜单 | 首期只读入口，版本动作后续 |
| History 修订行、Revgraph 节点 | 精确修订菜单 | 后续版本能力；首期只做已接通只读动作 |
| Diff 文本、预览文本/图片 | 内容菜单 | 首期基础 |
| Workspace 记录、Stream 记录 | 配置对象菜单 | 首期只读，修改后续 |
| 搜索结果 | 按文件 / CL 复用对应菜单 | 真实查询接通后；演示期仅复制和说明 |
| 页签、页签栏空白区 | 布局菜单 | 首期 |
| 终端、日志行、任务进度 | 工具内容菜单 | 首期基础，任务管理后续 |
| 固定活动栏、资源栏标题、工具栏、表头 | 布局/展示配置 | 首期按已有配置提供最小菜单 |
| 设置、地址框、搜索框及其他输入框 | 原生文本编辑菜单 | 保留原生，不自定义覆盖 |
| 磁盘状态、纯装饰区域 | 不需专用菜单 | 不新增 |

## 4. 文件和目录菜单

### 4.1 单文件：按以下分组和顺序

| 分组 | 候选项 | 条件与范围 |
| --- | --- | --- |
| 打开 | 文件预览；在新页签中预览 | 首期为本地文本/图片；无法判断类型时可进入预览页显示不支持原因 |
| 打开 | 其他软件打开…；系统中定位 | 桌面版、当前工作区内的真实本地文件；使用本地能力检查，不以 P4 状态代替文件存在性 |
| 版本获取 | 获取最新；获取指定版本… | 受控或已映射目标；指定版本必须有输入/确认界面；未提交修改需按动作策略处理，不静默强制覆盖 |
| 工作副本 | 签出…；添加到 P4…；标记删除…；还原… | 复用统一状态规则；省略号表示还需选择参数或确认 |
| 查看 | 差异（工作副本 ↔ have 版本）；历史；修订图 | 目标具备所需版本数据；不使用含糊的“Diff”掩盖比较双方 |
| 导航与复制 | 在工作区中定位；在 Depot 中定位；复制 ▶ | 只有可映射目的地才可用；复制子菜单见下文 |
| 刷新 | 刷新状态 | 只刷新相关数据，不自动同步文件 |

复制子菜单：文件名、本地绝对路径、工作区相对路径、Depot 路径；缺失路径置灰，不伪造。复制多项时按当前列表顺序每项一行，保持真实字符，不混入 shell 引号或 P4 通配符。

以下为后续扩展，不在首期菜单放占位：签出并用其他软件打开、移到 CL、还原未修改文件、解决冲突、变更文件类型、锁定/解锁、重命名/移动、从工作区移除、对账、合并/集成、复制/分支、撤销已提交变更、打标签。

### 4.2 文件夹、Depot 根、工作区根

- 浏览此目录、在文件页中显示；本地存在时支持系统定位。
- 获取最新 / 指定版本、签出、标记删除、还原：明确标注“递归”，范围是目录子文件。根目录操作额外提示“整个工作区/Depot 范围”。
- 本地目录支持“添加未跟踪文件…”：扫描递归子项，遵循忽略规则，不顺便签出修改文件或删除丢失文件。
- 在此目录搜索：打开唯一搜索页，设置目录范围；搜索尚为 UI 演示时必须明确告知，不产生假结果。
- 复制路径、刷新目录；后续增加“在此目录打开命令行”。
- 不提供单文件预览、文件 Diff、文件 History、文件 Revgraph、其他软件打开；目录历史/目录差异需独立聚合能力，不能把目录塞进单文件接口。
- Depot 根可能没有对应本地路径；不能默认等于工作区根。目录节点状态不是所有后代状态的汇总。

### 4.3 多选及混合选择

- 菜单顶部显示“已选择 N 项（文件 X / 文件夹 Y）”，不显示巨大文件名串。
- 首期支持：适用的批量获取、签出、添加、标记删除、还原、复制路径、刷新。系统定位、其他软件打开、预览、历史、修订图暂限单选。
- 同时选中父目录和其子项时，执行前合并覆盖范围；确认框展示最终范围及递归标记。
- 混合状态不静默跳过不适用项；统一禁用并提示原因/数量。未来若支持“仅操作适用项”，必须是用户明确选择的独立行为。
- 多选文件 Diff 首期不默认为两文件比较；后续恰好选两个文件时可显示“比较这两个文件…”，必须明确左右目标。
- 多个 CL 首期只复制编号/摘要，禁止无提示批量提交、删除、还原或 unshelve。

### 4.4 首期可用性重点

| 状态 | 常用可用项 | 重点限制 |
| --- | --- | --- |
| 未跟踪文件 | 本地查看、系统操作、添加、复制 | 无受控历史，不提供 P4 标记删除；首期不加入本地物理删除 |
| 忽略文件 | 本地查看、系统操作、复制 | 不默认强制添加或绕过忽略规则 |
| 已受控 / 落后版本 | 获取、签出、查看、标记删除 | 工作区修改及权限由执行前校验确认 |
| 已签出修改 | Diff、历史、还原、标记删除、本地查看 | 不重复签出 |
| 已打开添加 | 本地查看、还原、复制 | 未提交文件没有已提交历史；还原添加的影响须在确认中解释 |
| 已打开删除 | 历史、修订图、还原 | 本地可能存在（例如保留本地副本），系统动作依实际存在性决定 |
| 冲突 | Diff、查看、还原；后续解决冲突 | 不直接提供安全性未明确的更新/删除动作 |
| 未同步 / 本地缺失 | 获取、已有历史、修订图、Depot 路径复制 | 无本地预览或系统打开 |
| 未知 / 查询失败 | 复制已知标识、刷新 | 修改操作禁用并显示原因，不按“已受控”猜测 |

详细条件应在实现时与 `commandPolicy.ts` 合并成唯一规则；此表不是另写一套页面逻辑的依据。连接失效只影响需要 P4 的动作，本地查看/复制/系统能力不应被无关服务器错误一起禁用。

## 5. Changelist 与搁置对象

### 5.1 Pending CL 标题

- 首期基础：查看/展开详情、复制 CL 编号（Default 复制“default”）、复制描述、刷新；已编号非空 CL 可“提交整个 CL…”，必须复用验证与确认。
- 后续完整流程：编辑描述…、移动文件到其他 CL…、搁置…、还原整个 CL…、还原未修改文件、删除空 CL…。
- Default 不是可删除的编号 CL；不提供普通编号 CL 的删除/编辑入口。提交 Default 的“先创建编号 CL”流程未接通前禁用，并指引创建 CL。
- 非本人/非当前工作区/权限未知时，不开放修改；最终服务端校验仍为准。不能只看所有者名字就推断所有权限。
- 删除空 CL 需验证文件及 shelf 等约束；不是“强制删除非空 CL”。

### 5.2 Pending 中的工作文件

复用文件菜单，保留所属 CL 上下文。后续增加“移动到 CL…”“搁置选中文件…”“从当前 CL 还原选中文件…”。

**不提供名为“提交”的文件级入口却实际提交整个 CL。** 首期提交只放 CL 标题菜单。以后做选中文件提交，需要明确的移入新 CL / 提交流程。

### 5.3 Shelf 分组和搁置文件（后续）

- Shelf 分组：查看搁置文件、复制来源 CL、Unshelve 到 CL…、删除搁置内容…、刷新。
- 搁置文件：查看搁置内容、比较搁置版本与本地/基线、复制版本标识；支持范围明确后再增加“仅 Unshelve 选中文件”“仅删除选中搁置文件”。
- Unshelve 先选择目标工作区/CL并预检冲突；不叫“获取最新”。删除 shelf 明示删除服务器搁置副本，不等于删除工作文件。
- 不允许拿 shelf 的路径直接预览本地同名文件并标成“搁置内容”。

### 5.4 Submitted CL 与其中文件

- CL：查看详情、复制编号/描述、刷新。后续：查看整组差异、把工作区同步到此 CL…、撤销此 CL…。
- 文件：复制 Depot 路径/精确修订标识、查看历史/修订图、定位当前工作文件；后续增加“查看此修订”“与上一修订比较”“与工作副本比较”“获取此修订…”。
- 已提交 CL 不出现提交、移动文件、普通删除等 Pending 动作。撤销已提交变更是创建新待提交修改，不是删除历史。
- CL 编号与文件修订号不能混用；在此 CL 的状态与该 CL 中修改文件集合也不是同一范围。

## 6. 查看页和搜索结果

| 对象 | 菜单内容 | 语义/前置条件 |
| --- | --- | --- |
| History 修订行、Revgraph 节点 | 复制精确版本标识、打开所属 CL；后续查看此版本、与上一版本/工作副本/所选版本比较、获取此版本… | 保留 depotPath + revision + changeId；首期未接通项不展示 |
| 恰好两个历史修订 | 比较所选修订（后续） | 明示左右顺序；不把多个节点当成当前工作文件多选 |
| Diff 文本区域 | 复制选中文本、全选当前侧；文件导航入口 | 记录左/右侧及其来源；不能把历史侧内容冒充本地文件 |
| 文本预览 | 复制选择、全选、复制文件路径、系统定位、其他软件打开 | 内容操作只影响选择；系统动作只对当前预览对应的本地文件 |
| 图片预览 | 适应窗口、原始尺寸、复制路径、系统定位、其他软件打开 | 图片字节复制/另存为后续评估；不是“复制路径”伪装成“复制图片” |
| 文件搜索结果 | 按来源复用文件菜单，加“在所在目录显示” | 接入真实搜索后启用操作；缺少状态按需补齐 |
| CL 搜索结果 | Pending / Submitted / Shelf 对应菜单 | 仅按 CLID 查询，不重新加入独立的 CL 直达功能 |

锁定查看页的菜单永远作用于锁定对象，不使用最近在别处选择的文件。点击“在工作区中定位”可以改变工作区选择，但不能顺便改掉锁定页目标。

## 7. Workspace、Streams 与全局容器

### Workspace 记录

- 首期：查看详情、复制名称/根路径/Stream、刷新。路径缺失则对应复制项禁用。
- 后续：切换到此工作区…、编辑…、新建/复制配置…、删除工作区…。
- “切换”需处理未完成任务、连接、缓存和页签目标；不只是改下拉框文字。根路径属于其他主机时不能唤起本机目录；当前系统接口仅允许当前工作区范围，未扩展授权前不提供其他工作区的系统定位。
- 删除 Workspace 配置与删除本地目录分开；不默认强制，不静默丢弃 opened 文件或切换正在执行的任务上下文。

### Stream 记录

- 首期：查看详情、复制 Stream 路径/名称/父 Stream、刷新。
- 后续：查看相关工作区、创建工作区…、切换当前工作区到该 Stream…、编辑/新建子 Stream…、合并/复制向导…。
- 不凭菜单文字自动指定集成方向和目标；高级操作必须显式确认。暂无 Stream Graph 页签，不添加假入口。

### 列表空白区与资源树根

- 空白区：刷新当前列表、全选当前筛选结果、清除选择；有明确当前目录时提供复制目录路径、系统定位、在此搜索。
- Pending 空白区后续提供新建 CL；Workspace/Stream 空白区的创建功能随配置能力接通。
- 表头：后续可增加列显示、排序、重置列宽；没有对应设置能力前保留现有控件，不做空菜单。
- 空白处右键不复用上一行的删除/还原/提交菜单；页签空白区域也不冒用当前文件目标。

## 8. 页签和固定栏

### 页签标题

- 关闭、关闭其他页签、关闭右侧页签、关闭本组页签、关闭所有页签。
- 建议“其他/右侧/本组”只作用当前分屏组；“所有”作用当前窗口，不跨独立窗口。没有目标时禁用。
- 移到右侧分屏、移到下方分屏、移到其他已有组、弹出独立窗口：移动现有实例，不隐式复制全局页签。布局不支持的情况明确禁用。
- 文件类页签：锁定/解锁目标、复制目标路径、在新页签打开同一目标。锁定与防止关闭是两回事，锁定页签仍可关闭。
- 全局页签：不显示复制实例及目标锁定。单例校验必须覆盖独立窗口，已有实例应激活；跨窗口单例当前需要专门验证，不能假设现有布局库已处理。
- 关闭页签不等于取消 P4 操作。若后台任务继续，应在状态栏/日志可见；不能关闭 UI 就留下不可追踪任务。

### 固定栏与工具栏

- 左侧活动栏空白：显示/隐藏文字、打开设置；不加单项关闭，避免误删功能入口。
- 可折叠资源栏标题：折叠/展开、刷新当前资源视图。工作区与 Depot 固定入口不提供关闭。
- 底部命令行/日志栏标题：折叠/展开，不关闭或销毁固定工具。
- 顶部工具栏空白：显示/隐藏工具文字、打开相关设置；地址栏保持原生文本编辑菜单。

## 9. 命令行、日志和任务

- 命令行：复制所选文本、粘贴、全选、清空显示。粘贴需要用户手势，不能因右键打开菜单就读取剪贴板；多行或含回车文本需预览/确认，不自动执行。
- 文件夹的“在此打开命令行”（后续）：只设置明确的当前目录或准备命令，不把未经处理路径拼接成可执行 shell 文本；保持 P4 操作上下文一致。
- 日志行：复制消息、复制详细信息、按此操作筛选；导出后续提供脱敏选项。清空显示不等于删除持久化日志。
- 任务进度：查看相关日志；取消此任务（仅可取消时）。若聚合了多个任务，先展开任务列表，不能猜测取消对象；取消不回滚已完成部分。
- 密码、ticket、鉴权输入不进入复制日志/导出内容。

## 10. 与参考 P4V 截图的取舍

| 截图入口 | P4Deck 建议 |
| --- | --- |
| Open / Open With | 用明确的“文件预览 / 其他软件打开”，首期不另设含糊 Open |
| Get Revision、Check Out、Mark for Delete | 纳入首期，复用现有能力和确认规则 |
| History、Revision Graph、Diff Against Have | 纳入首期；需要精确版本时保留版本上下文 |
| Time-lapse | 暂不加入；历史页不是逐行时间演化，不能冒充已有能力 |
| Remove from Workspace | 后续，明确“移除本地受控副本”，与标记服务器删除分开 |
| Check Out and Open | 后续组合操作：签出成功后再打开，第二步失败不自动还原签出 |
| Diff Files Against | 后续比较向导，明确双方文件/版本 |
| Find in Streams | 后续，当前文件搜索不能冒充跨 Stream 关联查询 |
| Change Filetype、Merge/Integrate、Copy、Branch、Rename/Move、Undo、Tag | 后续高级子菜单，需参数、权限、预检与风险说明 |
| Bookmark | 暂缓，需要先有收藏存储和可访问入口 |

## 11. 交互、性能和安全契约

- 右键已选项保留整组；右键未选项改成该项单选。右键不触发双击打开。菜单快照记录选择集合、来源、连接、版本和主目标。
- 菜单打开后目标消失、连接/工作区切换、选择被其他交互替换时关闭菜单；点击动作时再次校验，不能操作刚刚切换进来的其他对象。
- 菜单采用统一浮层并限制到窗口可视范围；靠边翻转，过长内部滚动。子菜单最多一层，常用操作不藏在多级嵌套中。
- 点击外部、Escape、发起拖拽、源列表滚动/虚拟行卸载时关闭。菜单不依赖 DOM 行永久存在，只保存稳定对象标识。
- 支持 Shift+F10 / Context Menu 键、上下键、左右子菜单、Enter、Escape、焦点恢复；图标外必须有文本。禁用原因对键盘及读屏可访问。
- 只有已注册、验证过的快捷键才显示，不照搬 P4V 的 Ctrl+E 等；macOS 使用合适的 Cmd 展示并处理系统快捷键冲突。
- 每个窗口只挂一个菜单浮层；虚拟列表不为几万行各建一个菜单实例。菜单项和能力计算不可遍历整个 Depot。
- 能力检查复用连接/路径缓存和批量查询；本地存在性用本地检查；未知时不阻塞渲染、不将等待中的操作当成功。
- 修改动作交由统一任务层执行；只锁冲突操作，页面可交互。部分成功必须展示成功/失败范围，取消不能被标为全部回滚。
- 删除、还原、移除本地副本、覆盖、提交、批量/递归变更需要明确确认；只复制/打开菜单不会执行 P4 修改。

## 12. 建议实现组织（校验通过后再做）

1. `CommandRegistry`：命令 ID、名称、图标、快捷键、可用条件、风险类型；工具栏/右键/键盘共用。
2. `ContextTarget`：区分工作文件选择、目录、Pending CL、Submitted CL、Shelf、精确修订、Workspace、Stream、页签、日志/任务。
3. `MenuBuilder`：纯函数将对象和能力映射为菜单分组，不直接请求 P4，不在每个页面写条件分支。
4. `ContextMenuHost`：只负责定位、焦点、键盘、子菜单、关闭事件；不承载业务执行。
5. `CommandExecutor`：逐步从 `CommandBar.tsx` 提取执行/确认逻辑，工具栏不再充当所有菜单的隐式后端。选择快照与连接参数显式传入。
6. 服务层继续区分本地系统操作与 P4 操作；新增动作先验证请求契约、路径转义、批量范围，再开放菜单。

不在本轮提前抽象或改代码；先确定产品范围，再按首期最小集合落地，避免一次搭出大量无调用者的框架。

## 14. 本轮需要共同确认的决定

1. **首期范围**：建议先统一文件/目录/多选、页签、基础复制/导航；CL 完整流程与高级版本操作分批接入，不显示未完成占位项。
2. **打开默认行为**：建议文件“打开”明确叫“文件预览”；外部软件打开保持独立命令，不改变目前双击预览行为。
3. **多选查看**：建议首期继续限制预览/历史/修订图/系统打开为单选；暂不增加“一次打开几十个页签”。
4. **关闭范围**：建议其他/右侧/本组限当前分屏组，所有限当前窗口，不跨独立窗口。
5. **提交范围**：建议只在 CL 标题提供“提交整个 CL…”，暂不提供“提交所选文件”。
6. **新页签**：建议显式“在新页签中…”默认锁定目标，普通查看继续复用未锁定页签。
